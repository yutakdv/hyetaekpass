# 혜택패스 검증판 제품 인수기준

0.2.0 사용자 우선 과업은 현재 매장에서 가장 유리한 보유 카드·멤버십을 확인하고 등록한 코드를 제시하는 것이다. [서비스 상세 기준](service-experience-spec.md)·[실제 SX 결과](service-verification.md)를 함께 적용한다. 4탭·개인 조건 단계 작성·지갑/기본 수단·정적 QR/CODE128/EAN13·사용 순서·저장/최근·도움말·제보·관리 업무 화면을 구현했다. UNKNOWN이 남으면 전체 최대 할인이라고 주장하지 않는다. 아래 자료 권리·사람 원문 검수·실물 접근성·운영/출시 게이트를 유지한다.

기준일: 2026년 9월 30일 · 담당: 서비스 기획자 · 상태: 구현과 실제 검증 전 기준

이 문서는 고객 과업, 검증판 지원 범위, 기능별 인수기준을 정한다. 문서를 작성했다는 사실은 기능 구현·시험·이용 허가·실제 사람 검수·출시 완료의 증거가 아니다. 전체 범위는 [통합 사업기획서](../혜택패스_통합_사업기획서_최종.md), 개발 완료 조건은 [GOAL_PROMPT.md](../GOAL_PROMPT.md), 세부 조건은 아래 원문을 따른다.

이번 실행에서는 **서울 성수 생활권을 가정하고 가상 브랜드 3개로 개발 시험한다. 실제 브랜드 자료를 반입하지 않으며 공개 카탈로그는 0개다.** 사용자는 조건을 단말에서 직접 작성해 계산한다. 가상 자료는 개발·시험용으로 분리하고 실제 혜택·공식 검수 자료로 표시하지 않는다. 공용 위치 기능과 공개 자동 알림은 필요한 외부·기기 증거가 없으므로 OFF다.

## 1 고객 문제와 핵심 과업

초기 고객 가설은 같은 생활권의 매장을 반복 이용하고 카드·멤버십을 두 종류 이상 보유한 성인이다. 결제 전에 어떤 조건을 확인하고 어떤 순서로 혜택을 사용해야 하는지 이해하도록 돕는다. 고객에게 입력을 요구하는 제품의 가치와 자동 혜택 발견의 가치는 따로 검증한다.

| 과업 | 사용자가 끝내야 하는 일 | 관찰할 실패 |
|---|---|---|
| 지원 여부 확인 | 실제 지원 자료가 0개라는 상태와 개발용 가상 자료를 구별한다 | 가상 브랜드를 실제 지원 브랜드로 오해, 규칙 수를 생활 커버리지로 오해 |
| 보유 수단 정리 | 카드·멤버십 이름·버전·현재 등급을 로컬에 등록하고 수정한다 | 카드번호 요구, 버전·등급 자동 추정, 입력 포기 |
| 조건 확인 | 브랜드·점포·채널·금액과 필요한 실적·잔여 상태를 입력하거나 모름을 선택한다 | 잔여 전체 한도 가정, 점포명만으로 적용 가능 판단 |
| 계산 이해 | 즉시 할인, 지금 결제할 예상액, 청구 할인 예상액과 제외된 조건을 구별한다 | 청구 할인을 지금 결제액에서 차감, UNKNOWN을 0원 또는 적용 확정으로 오해 |
| 사용 준비 | 바코드 제시·예약·공식 앱 등 이용 순서와 입력 출처를 확인한다 | 계산 결과만 보고 필요한 사용 절차를 놓침 |
| 제어와 삭제 | 선택 기능을 거절·철회하고 로컬 지갑·조건·알림 상태를 삭제한다 | 권한 거절로 기본 사용 불가, 삭제한 동의·지역 자동 복원 |
| 문제 알리기 | 필요한 최소 설명으로 제보하고 삭제 토큰으로 자신의 제보를 삭제한다 | 지갑·좌표·토큰 자동 업로드, 제보 처리 화면 부재 |

실제 고객 가치 시험에서는 최근 결제 3건을 재구성해 혜택을 몰랐던 문제, 조건 이해 문제, 결제 전 기억 문제를 구분한다. 시작 가설은 10명 중 7명 이상이 3분 안에 유용한 혜택 또는 확인 항목을 찾는 것이다. 이는 제안 기준이며 아직 모집·실측하지 않았다. 입력 포기·자료 미지원·조건 미확인을 함께 기록하며, 가상 자료 과업 성공을 실제 브랜드 커버리지나 시장 수요의 증거로 삼지 않는다.

## 2 지원 범위와 우선순위

| 우선순위 | 범위 | 이번 검증판의 처리 |
|---|---|---|
| P0 | 지원 범위·빈 카탈로그·가상 자료 구분 | 공개 목록 0개를 정상 상태로 제공. 가상 브랜드 A/B/C 3개는 개발 모드에서만 제공 |
| P0 | 로컬 지갑·직접입력·수동 선택 | 계정 없이 사용. 이름·버전·등급·조건·입력일을 단말 저장 |
| P0 | 단순 예상 계산·조건 설명 | 한 카드와 최대 한 멤버십, 정률·정액, 명시된 기준·상한·반올림·순서만 지원 |
| P0 | 관리·API·DB 통합 | 허용 자료 후보 입력·형식 검사·검수 기록·미리보기·게시 게이트·차단·롤백·제보·감사 |
| P0 | 데이터 안전·전체 삭제·복구 | 빈 공개 카탈로그에도 권리·검수 게이트 및 차단·삭제 복구 검사 유지 |
| P0 | 양 OS 빌드·핵심 화면·접근성 | iOS·Android 앱과 실제 빌드 확인. 실기기 결과는 별도 기록 |
| P1 | 전경 주변 목록 | 가상 점포 목록·직접 지역 선택·단말 거리 계산을 개발 시험. 실제 공용 기능은 권리·절차·기기 게이트 전 OFF |
| P1 | 선택형 배경 알림 | 상태·정책·권한 연동과 설치 가능한 시험 경로 준비. 공개 flag는 OS·장소별 OFF |
| P1 | 자료 보조 | 표준 파서로 후보·변경 비교, 수동 경로 유지. AI에 게시 권한 없음 |
| 외부 게이트 | 실제 브랜드 카탈로그·공용 위치·AWS 운영·스토어 공개 | 필요한 권한·주체·기기·실제 검수·법률·비용·제출 증거를 확보한 범위에서 판단 |

P0는 검증판의 필수 범위다. P1도 Goal의 구현·시험 준비 항목이며, 외부 게이트 미충족을 구현 완료로 바꾸지 않는다. 공용 기능 OFF는 실제 기기 연동과 시험 준비를 생략하는 근거가 아니다.

초기 제외: 계정, 클라우드 지갑 동기화, 금융 실적 자동 조회, 카드 발급, 결제, 영수증 OCR, 개인 쿠폰 자동 수집, 포인트 원화 최적화, 전국 카탈로그, B2B, 런타임 LLM·RAG, 상시 AI 서비스. 천원당 할인·포인트·무료 상품·복잡한 공유 한도·선착순은 초기 자동 합산에서 제외하고 의미와 이유를 안내한다.

## 4 기능별 인수기준

각 기준의 결과는 `통과`, `실패`, `미실행`, `외부 조건 미충족` 중 하나로 기록한다. 구현 파일이 존재하는 것만으로 통과하지 않는다. 아래 기준은 요구사항이며 현재 통과 결과가 아니다.

| ID | 기능 | 통과를 판정할 관찰 가능한 기준 |
|---|---|---|
| APP-01 | 지원 범위·데이터 구분 | 첫 화면에서 실제 공개 카탈로그 0개와 사용자 직접입력 경로를 확인할 수 있다. 개발 자료에는 가상·개발용 표시가 있고 공개 목록·실제 브랜드 지원 수로 집계되지 않는다 |
| APP-02 | 로컬 지갑 등록·수정 | 카드·멤버십 한 개부터 저장·수정·삭제·재실행 보존이 된다. 상품 버전·등급 모름을 저장한다. 카드번호·CVC·금융 로그인 입력란이 없고 지갑·개인 조건 업로드가 없다 |
| APP-03 | 사용자 직접 작성 | 작성자가 사용자이며 입력일·미검수·출처 미입력 상태를 표시한다. 사용자가 이름·대상·채널·기간·지원 산식·조건·사용 순서를 입력/수정한다. 누락한 기준·반올림·중복을 앱이 만들어 채우지 않는다. 공동 카탈로그로 자동 편입되지 않는다 |
| APP-04 | 수동 선택·조건 입력 | 위치·알림 권한 없이 브랜드·점포·채널·금액을 선택/입력할 수 있다. 필요한 실적·등급·잔여 횟수·한도는 충족/미충족/모름으로 입력하고 기준월·확인시각·혜택 버전에 묶는다. 변경·월 전환 때 다시 확인한다 |
| CALC-01 | 단일 계산 권위·입력 검사 | 모바일과 관리 미리보기가 동일한 순수 TypeScript 엔진을 사용한다. 한 카드+최대 한 멤버십만 조합한다. 정수 원화·명시된 비율 단위로 계산하고 음수·비정수·안전 범위 초과·대상금액 초과·할인액이 기준금액을 넘는 입력을 거부한다 |
| CALC-02 | TRUE/FALSE/UNKNOWN | TRUE만 지원 조건 충족 후보로 계산한다. FALSE는 이유와 함께 제외한다. UNKNOWN은 기본 합계와 조합 순위에서 제외하며 확인할 항목을 표시한다. 잔여 모름을 전체 한도 잔존으로 해석하지 않는다 |
| CALC-03 | 합산·순서·시나리오 | 조합별 중복 허용·순서·후속 기준금액 근거가 모두 있어야 합산한다. 문구 부재를 허용으로 해석하지 않는다. 자격만 UNKNOWN이고 산식·기준·상한·반올림·순서가 모두 확정된 경우에만 별도 조건부 시나리오를 제공하고 기본 합계와 분리한다 |

### 위치 개발 시험의 시작값

가상 장소 시험은 상태 로직 검사이며 물리적인 위치 품질의 통과 증거가 아니다. 문서의 시작값은 후보 반경 150m·5~10개 점포/묶음, 실제 유효 위치 3회 이상·첫~마지막 120초 이상·간격 60초 이하·마지막 30초 이내·정확도 50m 이하·거리+정확도≤반경, 첫 실제 관측 후 후보 수명 5분이다. 실제 관측을 얻지 못하면 보류/만료한다. 조정은 버전·근거를 남기며 공용 flag를 자동 활성화하지 않는다.

실기기 품질 시험은 [위치 정책](01_위치알림_정책과_검증.md)의 사례·표본·지표를 따른다. 횡단보도·정류장·정체·다른 층·짧은 결제·잠금·절전·강제/시스템 종료·재부팅을 포함한다. 자동 대상 제외 장소의 방문도 coverage 분모에 포함하고, 지역 안내·전체 발견·결제 전 도달·미수신을 따로 보고한다. 오탐 5%·적절성 90%·coverage 70%·배터리 추가 중앙값 3%p는 수용 가설이며 작은 표본의 점추정으로 통과를 선언하지 않는다.

## 6 제품 카피 기준

| 화면/상태 | 사용할 문구 |
|---|---|
| 소개 | 결제 전에, 입력한 혜택 조건을 확인하세요. |
| 공개 카탈로그 빈 상태 | 현재 공개할 수 있는 검수 혜택은 없어요. 직접 입력한 조건으로 계산할 수 있어요. |
| 개발 자료 | 가상 브랜드 · 개발 시험용 조건입니다. 실제 매장에서 사용할 수 없어요. |
| 로컬 지갑 | 보유 수단과 입력 조건은 이 기기에 저장해요. 카드번호나 금융 로그인 정보는 입력하지 마세요. |
| 사용자 입력 | 직접 작성한 조건 · 입력일 {날짜} · 공식 원문 검수를 거치지 않았어요. |
| 예상 결과 | 입력하고 확인한 조건 기준 예상이에요. 실제 적용은 상품과 매장의 조건을 확인하세요. |
| 금액 표시 | 즉시 할인 예상 / 지금 결제할 예상액 / 청구 할인 예상 |

| 조건부 시나리오 | {조건}을 충족한다면 가능한 예상이에요. 기본 합계와 별도로 확인하세요. |
| 중복 미확인 | 함께 적용되는지 확인되지 않아 두 혜택을 합산하지 않았어요. |
| 안내 전용 | 이 할인 방식은 아직 계산을 지원하지 않아요. 조건과 사용 절차를 확인하세요. |
| 만료/차단 | 이 자료로 새 계산을 할 수 없어요. 갱신하거나 입력 내용을 확인하세요. |

| 제보 | 카드번호·연락처·정확한 위치 등 개인정보를 쓰지 마세요. |

사용하지 않을 주장: 전국 모든 혜택, 최대 할인/실제 적용/절감액 보장, 매장 입장 감지, 2분 뒤 반드시 알림, AI 검수 완료를 독립 사람 검수로 표현, 계정 없음으로 개인정보 수집 전무 주장, 이름 조사로 상표권 확보 주장, AWS 실행으로 두 스토어 출시 완료 주장. 잠금화면 알림 문구는 해당 기능 활성화 게이트를 통과한 경우에만 사용하며 실제 광고 분류에 따른 표시·발신자·연락처·철회 요건은 별도로 반영한다.

## 7 진행·중단 조건과 읽은 근거

자료 권리나 실제 독립 검수자가 없으면 고위험 사전 탑재 계산 공개를 보류하고 빈 카탈로그·로컬 직접입력을 유지한다. 입력형 과업에도 가치가 없으면 자동 발견 확대를 중단하고 제품 가설을 다시 검토한다. 위치 실행 기회·결제 전 도달·누락·오탐·피로가 기준을 만족하지 못하면 해당 OS/장소/모드를 끈다. 운영·지원이 실제 팀 가용시간의 20%를 2주 연속 넘으면 신규 소스 추가를 동결한다. 검수 부재·접근 실패를 확인일만 갱신하는 것으로 처리하지 않는다.

다음 문서를 처음부터 끝까지 읽어 작성했다. 현재 공식 정책·가격·법률·상품 조건을 새로 재검증하거나 외부 연락·실기기 시험을 수행한 결과는 포함하지 않는다.
