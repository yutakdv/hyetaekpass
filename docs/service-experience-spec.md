# 혜택패스 서비스 경험 명세

2026-09-30 · 서비스 기획자 · 구현 인계용 설계 · 기준 작업 트리 `faf30de` 이후

목표는 **결제 직전, 내 카드·멤버십의 필요한 조건과 사용 순서를 빠르게 확인하는 앱**이다. 서비스 문구는 “결제 전에, 조건을 또렷하게.”를 유지한다. 이 명세는 화면·세부 기능·상태·인수 기준을 정하며 구현·실사용 가치·공개 출시 완료를 주장하지 않는다. 총괄은 이 명세를 구현 계획과 실제 앱으로 연결한다.

기준은 [원기획](../혜택패스_통합_사업기획서_최종.md), [기존 인수 기준](product-acceptance.md), [데이터 조건](02_할인데이터_확보와_운영.md), [위치 정책](01_위치알림_정책과_검증.md), [아키텍처](03_아키텍처_Docker_AWS.md), [개인정보](05_법률개인정보_및_출처.md), [개발 Goal](../GOAL_PROMPT.md)이다. 실제 서비스 경험의 확대는 계산·권리·개인정보 경계의 완화를 의미하지 않는다.

## 1 사용자와 가치 가설

20~40대 성인, 생활권 한 곳의 반복 결제, 카드·멤버십 두 종류 이상 보유는 **기획 가정**이다. 성수 생활권·2~3개 브랜드·테스터 수와 선호는 미확인이다. 실제 권리 확보된 공개 자료는 현재 0개다. 첫 대상은 “혜택을 알지만 조건·순서를 기억하기 어려운 사람”이며 전국 자동 추천과 결제 대행을 약속하지 않는다.

| 상황 | 사용자가 하려는 일 | 서비스의 완료 상태 |
|---|---|---|
| 매장 줄에서 결제 직전 | 익숙한 브랜드의 저장 조건과 내 수단을 골라 금액 확인 | 사용 순서·확인할 조건·서로 구분한 예상 금액을 읽음. UNKNOWN이면 확인 항목을 읽음 |
| 공식 앱에서 혜택을 찾은 직후 | 다음 결제에 다시 볼 조건을 내 지갑에 기록 | 내 조건 저장·출처 종류/작성일·필요 조건·기간이 남고 상세로 이동 |
| 멤버십 등급 또는 카드 버전 변경 | 지갑 수정 후 기존 조건 재확인 | 관련 개인 자격을 UNKNOWN으로 무효화하고 다음 계산에서 다시 질문 |
| 연결이 끊긴 매장 | 저장해 둔 내 조건 확인 | 유효한 개인 기록 사용. 공개 자료는 안전 기한 이내만 사용하며 기한 초과는 숫자를 보류 |
| 혜택 정보가 다른 경우 | 문제 내용을 최소한으로 제보하고 필요하면 삭제 | 제출 여부와 단말 보관 여부를 구별하고 본인 제보 삭제 완료를 확인 |
| 더 이상 사용하지 않음 | 항목 또는 단말 자료를 삭제 | 범위 확인 후 실제 삭제. 서버 제보를 단말 삭제로 삭제했다고 표시하지 않음 |

**60초 핵심 과업**은 지갑/조건이 준비된 재방문 사용자가 홈 또는 저장에서 결제 확인을 열어 결과 또는 확인 필요 이유에 도달하는 시간이다. 신규 조건의 원문 읽기·작성·실제 검수 시간을 60초에 포함해 성공을 꾸미지 않는다. 신규 사용자의 별도 목표는 60초 안에 지갑 하나를 등록하거나 현재 자료 없음과 내 조건 경로를 이해하는 것이다. 실제 시간·성공률은 관찰 후 기록한다.

## 2 현재 화면에서 바꿀 문제와 구현 범위

현재 `FE/mobile/App.tsx`와 `src/model.ts`를 코드 그래프의 App·emptyLocal·updateWallet·submitReportSafely로 확인했다. 기능은 존재하지만 혜택 탭 하나에 모드·원시 필드·조건·결과가 길게 이어지고, 가상 예시/서버 시각/개발 endpoint가 일반 흐름에 노출된다. 별도 홈·검색·저장·상세·첫 실행과 결제 확인의 단계/뒤로 복원이 필요하다. 기존 지갑·직접 작성·제보 영수증·안전 정책은 유지하고 저장 구조를 호환 확장한다.

| P0로 이번에 구현할 기능 | 최소로 완결할 사용자 과업 |
|---|---|
| 첫 실행·홈 | 권한 없이 시작, 지갑 한 개 등록 또는 나중에, 결제 확인 진입·저장/최근 이어 보기 |
| 탐색·상세 | 이름 검색·자료 종류/채널 필터·빈 결과·상세·저장·관련 수단·출처·이용 순서 |
| 결제 전 확인 | 세 단계, 필요한 질문만, 모름 유지, 결과별 다음 행동, 입력 변경 즉시 재평가 |
| 지갑·내 조건 | 등록/수정/삭제·연결 조건·기본 수단 선택·서비스 단위 입력·미완성 기록 안전 저장 |
| 저장 | 즐겨찾기·최근 확인, 검색·해제·삭제, 만료/차단/삭제된 참조 처리 |
| 설정·도움말 | 개인정보·동의/철회·자료 상태·전체 삭제·FAQ·제보·앱 정보/개발 진단 분리 |
| 제보 후속 관리 | 제출 중복 방지·로컬 접수 목록·내용 수정 경로·명시적 삭제 확인/재시도 |

초기 제외는 계정·클라우드 지갑 동기화·금융 실적/잔여 자동 조회·결제·카드 발급·영수증 OCR·쿠폰 자동 수집·포인트 원화 최적화·전국 통합·B2B·런타임 LLM이다. 최근 확인은 거래내역이 아니며 월 절감액·실제 적용액·누적 수익 숫자를 생성하지 않는다. 주변 자동 알림은 공개 OFF를 유지한다. 실제 이용권·사람 원문 검수·법률·기기·AWS·스토어 게이트는 [검증 레저](verification-ledger.md)에 남긴다.

## 3 정보 구조와 이동

하단 탭 이름은 **홈 / 탐색 / 지갑 / 저장**으로 통일한다. 설정은 홈 상단의 레이블 있는 설정 버튼으로 진입한다. 상세·지갑 편집·내 조건 편집·결제 확인·제보·도움말은 탭 위의 화면 스택으로 연다. 새로운 내비게이션 의존성은 실제 필요를 확인한 경우만 추가한다.

| 화면 ID | 진입 | 핵심 행동·종료 |
|---|---|---|
| FIRST | 설치 후 최초 실행 | 시작하기→지갑 추가 또는 나중에→홈. 위치/알림 요청 없음 |
| HOME | 기본 탭·완료 후 복귀 | 결제 전 확인, 내 조건 추가, 최근/저장 상세, 설정 |
| EXPLORE | 탐색 탭 | 검색/필터→DETAIL. 자료 0개면 내 조건 추가 또는 지갑 등록 |
| DETAIL | 목록·저장·최근·지갑 연결 조건 | 결제 확인·저장/해제·공식 경로·내 조건 수정·제보 |
| CHECK_TARGET | 홈·상세 | 브랜드/대상·채널·한 카드/최대 한 멤버십→CHECK_INPUT |
| CHECK_INPUT | 대상 선택 후 | 결제 금액·필요한 자격/잔여·모름→CHECK_RESULT |
| CHECK_RESULT | 입력 검사 성공 | 이용 순서/예상/확인 필요→조건 수정·다른 수단·상세·완료 |
| WALLET | 지갑 탭 | 보유 수단·연결 내 조건→등록/수정/삭제·내 조건 추가 |
| SAVED | 저장 탭 | 즐겨찾기/최근 확인→상세 또는 다시 확인·해제/기록 삭제 |
| SETTINGS | 홈 상단 | 개인정보·동의/삭제·자료 갱신·HELP·REPORTS·ABOUT |
| REPORTS | 설정·제보 성공 | 접수 영수증 목록·수정 제출 경로·본인 서버 삭제 |

뒤로 이동은 이전 화면의 검색·스크롤·선택을 복원한다. 탭 전환은 미완료 결제 입력을 메모리에 유지한다. 체크를 새로 시작하면 기존 내용을 이어 볼지 명시적으로 선택한다. 앱 재실행 뒤 금액과 개인 자격을 과거 거래처럼 복원하지 않는다. 수정 중 뒤로 가면 “작성을 취소할까요?”와 “계속 작성/취소”를 제공한다. 네트워크 오류가 스택이나 지갑 상태를 초기화하지 않는다.

## 4 첫 실행과 홈

첫 실행 한 화면에서 목적과 로컬 저장 사실을 설명한다: “가진 카드·멤버십의 조건을 결제 전에 확인해요.” / “지갑과 내 조건은 이 기기에 저장해요.” CTA는 “시작하기”, 다음 선택은 “지갑에 하나 추가”와 “나중에”다. 미확인 법률 동의문을 완료된 약관처럼 게시하지 않는다. 선택 권한을 일괄 요청하지 않는다. 완료 기록은 단말에 저장하고 전체 삭제 후 첫 실행으로 돌아간다.

홈은 인사·목적 한 문장, 주 CTA “결제 전 확인”, 보유 수단 요약, 저장한 조건/최근 확인의 순서다. 지갑이 비었으면 “내 카드·멤버십을 하나 추가해 보세요”와 등록 CTA를 보여준다. 내 조건이 없고 public0이면 “아직 제공할 혜택이 없어요. 알고 있는 조건을 기록해 다음 결제에 확인할 수 있어요.”와 “내 조건 추가”를 제공한다. 자료 부재를 연결 오류나 서버 점검으로 표시하지 않는다.

홈에는 규칙 수·서버 시각·안전 revision·raw ID·API endpoint·DEBUG 플래그를 표시하지 않는다. 실제 행동이 없는 비활성 “곧 공개” 카드나 가상 추천 목록을 만들지 않는다. 현재 확인할 대상이 없을 때 결제 확인 CTA는 설명/내 조건 추가로 연결되며 무반응 버튼이 되지 않는다. “내 조건 추가” 진입에 지갑이 비었으면 수단 등록을 먼저 열고 저장 뒤 원래 조건 작성으로 돌아온다. 도움말에서 서비스 제공 범위와 공개 자료 없음의 사실을 확인할 수 있다.

## 5 탐색과 상세

탐색은 검색어를 브랜드/조건 제목/보유 수단 이름에 적용하고 “전체 / 내 조건 / 제공 자료” 필터, “매장 / 온라인 / 공식 앱” 채널 필터를 제공한다. 여러 필터에 결과가 없으면 “검색 결과가 없어요”, “필터 초기화”, “내 조건 추가”를 보여준다. public0에서는 제공 자료 필터 자체가 빈 정상 상태다. 개인 조건과 향후 실제 제공 자료를 동시에 볼 수 있어도 각 카드에 **내가 기록한 조건 / 자료 원문 검수** 출처 종류를 붙이며 합산·권리 경계를 바꾸지 않는다. 가상 fixture는 일반 목록에서 검색되지 않는다.

카드는 제목·대상·관련 수단·채널·기간·상태를 보여준다. 결제 금액 입력 전 실제 절감액을 추정해 크게 표시하지 않는다. 정률/정액 문구는 출처 종류와 함께 보여주며 UNKNOWN/안내 전용/만료를 별도 표시한다. 거리순은 권리·전경 기능 gate가 충족됐을 때 사용자가 요청한 단말 계산만 허용한다. 현재는 지역 직접 선택과 검색을 우선하며 지도/주변이라는 이유로 실제 자료가 있는 듯한 화면을 만들지 않는다.

상세 순서는 제목·출처 종류/상태→사용할 수단/채널→결제 전 사용 순서→필요 조건/제외→기간/확인일/출처→행동이다. 하단 주 CTA는 “결제 전 확인”, 보조는 저장, 공식 조건 보기, 제보다. USER_INPUT은 “내가 기록한 조건 · 원문 미검수”와 작성/수정일을 유지한다. 개인 기록에는 수정/삭제를 제공하고 제공 자료는 사용자 편집을 허용하지 않는다. URL이 없으면 “확인 링크 없음”, 잘못된 URL이면 입력 오류를 보여주며 가짜 공식 링크를 생성하지 않는다. 공식 링크는 허용된 HTTPS 웹 링크를 기본으로 하고 미확인 앱 딥링크를 필수 경로로 쓰지 않는다.

만료·차단 상세는 숫자/계산 CTA를 보류하고 가능한 메타데이터·이유·갱신/다른 조건을 제공한다. 철회 권리 때문에 지워야 하는 제목·본문은 저장 카드에도 복제하지 않는다. “저장한 자료를 더 이상 제공하지 않아요”와 제거 동작만 남긴다.

## 6 결제 전 확인 세 단계

1. **대상 선택:** 상세에서 들어오면 브랜드·규칙·채널을 채우고 사용자가 확인한다. 홈에서는 저장/최근/검색으로 고른다. 카드 하나와 멤버십 최대 하나만 선택하며 지갑에 없는 수단은 등록 경로를 제공한다. 버전 모름을 자동 상품 확정으로 바꾸지 않는다. 점포 모름을 허용하고 필요 조건으로 남긴다.
2. **금액·조건:** 금액은 원 단위 양의 정수, 상한은 기존 계약 1,000,000,000원이다. 숫자 키패드·천 단위 표시·필드 단위 오류를 제공한다. 대상 품목 금액은 필요한 규칙에만 묻고 총액보다 크면 해당 필드에 오류를 붙인다. 관련 규칙의 실적·등급·품목/점포·버전·잔여 한도/횟수만 질문한다. 기본값은 모름이고 충족을 미리 선택하지 않는다. 기존 응답은 같은 기준월·규칙 버전·상품/등급에서만 재사용하며 변경 때 재질문한다.
3. **결과:** 먼저 제시/예약 등 실제 사용 순서를 보여준다. 즉시 할인 예상, 지금 결제액 예상, 청구 할인 예상을 별도 행으로 표시한다. UNKNOWN이면 숫자 대신 확인할 조건/공식 경로를 표시하며 0원으로 바꾸지 않는다. FALSE·소진·대상 밖은 구체적인 이유와 조건 수정 경로를 제공한다. 계산 가능한 다른 후보와 미확인 항목을 섞어 최대 할인이라고 순위를 만들지 않는다.

계산은 기존 단일 TypeScript 엔진만 사용한다. 사용자 입력은 별도 개인 모드로 평가하고 제공 자료와 합쳐 출처 불명 합산을 만들지 않는다. USER_INPUT의 카드/멤버십 중복 합산은 기존 미지원 그대로다. 산식·순서·반올림·중복 자체가 UNKNOWN이면 가정 숫자를 만들지 않는다. 월 전환·시간 불확실·새 차단은 화면에 있던 결과도 무효화한다. 값·대상·수단·조건을 수정하면 이전 결과를 즉시 보류하고 재평가한다.

주 CTA “확인한 조건으로 계산”, 결과 뒤 “조건 수정”, “다른 수단 확인”, “확인 완료”를 제공한다. 완료는 최근 확인에 대상 참조만 남기며 결제 완료나 실제 적용으로 저장하지 않는다. 금액·자격 응답·예상액은 최근 목록의 숫자 기록으로 남기지 않는다. 저장 결과의 과거 숫자를 다음 방문에 재사용하지 않는다.

## 7 지갑과 내 조건 작성

지갑은 카드/멤버십 섹션과 이름·등급/유형·버전 또는 모름, 연결된 내 조건 수를 보여준다. 기본 선택 수단은 사용자가 별표로 고른 카드/멤버십이며 자동 유리한 상품 추천이 아니다. 등록은 이름/종류가 필수, 등급/유형·상품 버전은 모름 허용이다. 카드번호·CVC·계좌·금융 로그인을 받지 않는다. 보호 저장이 성공한 뒤 목록에 반영하고 실패 시 입력을 유지한다. 중복된 같은 상품은 기존 항목 수정으로 안내하되 사용자가 이름만 같다고 별개 버전을 잃지 않도록 한다.

수단 수정 시 이름만 변경하면 연결을 유지한다. 종류·등급·버전 변경은 관련 개인 조건을 UNKNOWN으로 무효화한다. 수단 삭제 확인은 “이 수단과 연결된 내 조건 N개가 함께 삭제돼요”처럼 실제 영향을 보여주고, “취소/삭제”를 제공한다. 연결된 즐겨찾기/최근/기본 선택 참조도 함께 정리한다. 삭제가 저장에 실패하면 성공 문구를 띄우지 않는다.

내 조건 작성은 **기본 정보→할인 내용→기간·사용 순서→요약**으로 나눈다. 기본 정보는 제목·브랜드·연결 수단·채널이다. 할인 내용은 “정률 % / 정액 원 / 메모만”으로 표시하고 UI의 %를 최대 소수 두 자리로 받아 정수 bp로 변환한다. bp·UTC·JSON은 일반 입력 레이블에 쓰지 않는다. 최소금액·상한·기준금액·반올림·정산 시점은 접힌 “계산 조건”에서 설명과 함께 명시적으로 선택한다. 앱이 미확인 값·상한·반올림을 만들어 채우지 않는다.

기간은 한국 날짜/시간 선택으로 입력하고 저장 시 기존 UTC 반개구간 계약으로 변환한다. “날짜만 종료”는 해당 KST 종료일 다음 날 00:00을 endsAt로 사용한다. 기간 미확인은 계산 승인 없이 기록만 저장한다. 새 기록에 30일 기간을 임의 부여하지 않는다. 출처 링크는 선택, 사용 순서/제외는 짧은 문장 입력이다. 필수 계산 의미가 빠졌거나 천원당/포인트 등 초기 미지원은 “메모만”으로 저장하고 숫자 계산을 하지 않는다. 완성된 규칙과 미완성 draft는 별도 저장하며 draft를 기존 Rule로 억지 생성하지 않는다. 요약에 “내 기록 · 원문 미검수”·입력한 산식/기간을 읽은 뒤 저장한다. 수정은 새 버전으로 저장하고 이전 개인 자격 응답을 무효화한다.

## 8 저장과 최근 확인

저장은 “즐겨찾기 / 최근 확인” 전환으로 구성한다. 즐겨찾기는 rule/brand 참조와 저장일, 최근은 마지막 확인한 rule/brand 참조와 확인일만 단말에 둔다. 최대 즐겨찾기 40개·최근 10개를 시작 한도로 정한다. 실제 저장소 한도에 맞추되 데이터 유실 대신 초과 안내를 제공한다. 검색·최신 순 정렬·즐겨찾기 해제·최근 기록 전체 삭제를 지원한다. 최근 기록 전체 삭제는 지갑/조건을 삭제하지 않는다.

빈 상태는 “자주 확인할 조건을 저장해 보세요”와 탐색/내 조건 추가다. 최근 빈 상태는 “결제 전 확인한 조건이 여기에 모여요”다. 날짜/규칙 버전이 달라졌으면 “다시 확인 필요”, 만료는 “기간 종료”, 차단은 “안내 중지”를 붙인다. 없는 참조는 unavailable 카드로 처리하고 자동으로 다른 규칙으로 연결하지 않는다. 링크를 누르면 현재 유효한 상세/결제 확인을 새로 평가한다. 저장은 자료 권리를 연장하거나 차단을 우회하지 않는다.

## 9 설정·도움말·제보·삭제

설정은 내 정보의 처리, 선택 기능/권한, 자료 확인, 도움말, 내 제보, 앱 정보, 단말 자료 전체 삭제로 구성한다. “지갑과 내 조건은 이 기기에 저장해요. 제보할 때 입력한 내용은 서버로 보내요”처럼 처리별 사실을 설명한다. 접속 로그/IP·운영자 인증·SDK 처리까지 개인정보가 없다고 말하지 않는다. 자동 알림 OFF는 “주변 자동 안내는 아직 제공하지 않아요”와 수동 경로를 안내하고 작동 가능한 toggle처럼 보이게 만들지 않는다.

위치/알림 권한은 사용자가 해당 기능을 요청할 때 목적 설명 뒤 요청하며 거절은 직접 지역/점포 선택으로 복귀한다. 공개 gate OFF면 OS 권한을 받아도 기능을 켜지 않는다. 철회는 먼저 OFF→OS 작업/알림 정리→단말 상태 정리하며 일부 실패는 단계/재시도를 보여준다. 개인정보/동의 버전·실제 변경일은 상세에서 조회한다.

도움말 FAQ는 “혜택이 없을 때”, “내 조건과 제공 자료 차이”, “조건 모름”, “청구 할인과 현재 결제액”, “오프라인”, “자료 삭제”, “앱 삭제와 단말 전체 삭제”, “제보 수정/삭제”다. 응답 담당·시간이 미확인인 상태에서 실시간 상담·24시간 답변을 약속하지 않는다. 지원 경로는 앱 제보와 제공 가능한 문서이며 존재하지 않는 이메일/전화/URL을 넣지 않는다.

제보는 상세에서 rule 참조를 채우고 설정에서는 일반 제보로 시작한다. 종류와 2,000자 이내 설명만 보내며 지갑·금액·좌표·과거 계산을 자동 첨부하지 않는다. 짧게 “카드번호·연락처 등 개인정보는 넣지 마세요”를 입력 옆에 둔다. 제출 중 중복 탭을 막고 실패하면 입력을 유지한다. 성공은 201과 삭제 영수증의 보호 저장이 확인된 뒤 표시한다. 보호 저장 실패는 기존 보상 삭제/재시도를 유지하고 접수 성공만 단정하지 않는다.

접수 목록은 단말 영수증과 날짜/종류를 보여주며 raw 삭제 토큰은 기본 화면에서 숨긴다. 토큰은 사용자가 보관을 요청한 별도 화면에서만 열고 URL·로그·공유·분석에 넣지 않는다. 기존 API에는 사용자 처리 상태 조회/내용 PATCH가 없으므로 **P0 후속 수정은 사용자가 확인한 기존 제보 삭제→수정 내용 새 제출**로 구현한다. 버튼은 “내용을 수정해 다시 보내기”이며 “기존 제보를 삭제한 뒤 새로 접수해요”를 확인한다. 삭제 실패면 새 제보를 보내지 않는다. 삭제 성공·새 제출 실패면 “기존 제보는 삭제됐어요. 수정 제보를 다시 보내주세요”와 작성 내용을 유지한다. 새 접수는 새 영수증을 저장한다. 자동 재시도·중복 성공을 만들지 않는다. 처리 상태를 서버에서 조회하지 않았으면 “접수됨”만 표시하고 OPEN/CLOSED를 추정하지 않는다.

제보 삭제 확인은 “서버에 보낸 이 제보를 삭제할까요?”와 취소/삭제다. 204 뒤 로컬 영수증을 정리한다. offline/401/429/503에서는 실패 이유와 재시도를 보여주며 토큰을 버리지 않는다. 서버 제보 삭제가 완료됐는데 단말 정리만 실패한 경우 두 결과를 구분한다. 내용 수정 및 상태 조회의 새로운 API는 후속 운영 필요가 확인되면 별도 최소 계약으로 추가하며 이번 UI를 위해 계정을 만들지 않는다.

단말 전체 삭제 확인에는 지갑·내 조건·draft·즐겨찾기·최근·캐시·동의·보호 키·위치 작업·알림을 나열한다. 서버 제보 수가 있으면 “서버 제보는 별도 삭제예요. 제보 삭제 정보도 이 기기에서 지워져요”와 제보 관리/취소/단말 삭제를 제공한다. 연결 문제로 단말 삭제를 막지 않는다. 전체 삭제 후 첫 실행 상태로 돌아가고 삭제한 수단·선택 동의가 자동 복원되지 않아야 한다. iOS Keychain·신뢰 OS backup·재설치의 실제 검증은 미수행 사실을 앱 정보와 시험 문서에 둔다.

|---|---|---|
| 로컬 저장 로딩 | “저장한 내용을 불러오고 있어요”·탭 영역 안정 유지 | 실패 시 다시 불러오기. 지갑이 빈 것처럼 보여주지 않음 |
| API 로딩 | 작은 “자료 확인 중”·개인 기록 사용 유지 | 갱신 취소/나중에. 전체 앱 차단 없음 |
| 공개 정상 빈 자료 | “아직 제공할 혜택이 없어요”·public0 사실 유지 | 내 조건 추가·지갑 등록 |
| 지갑 빈 상태 | “가진 카드·멤버십을 하나 추가해 보세요” | 수단 추가·나중에 |
| 검색/필터 빈 결과 | “검색 결과가 없어요” | 필터 초기화·검색 수정·내 조건 추가 |
| 개인 기록만 있음 | 내 기록·미검수 label, 제공 자료처럼 설명하지 않음 | 내 조건 상세/결제 확인 |

| UNKNOWN | “확인할 조건이 남아 있어요”·숫자 제외 | 필요한 조건만 확인·모름 유지·공식 링크 |
| FALSE/소진/대상 밖 | “입력한 조건에서는 사용할 수 없어요”+이유 | 조건 수정·다른 수단 |
| 안내 전용/미완성 draft | “계산 없이 기록한 내용이에요” | 상세 메모·필요 의미 추가, 가짜 숫자 없음 |
| offline·기한 유효 | “오프라인 · 마지막 확인 자료”·실제 기한 표기 | 유효 범위/개인 기록 사용·갱신 |
| 기한 만료/시간 불확실 | “최신 자료 확인이 필요해요”·이전 숫자 제거 | 자료 갱신·개인 기록/지갑 유지 |
| 새 차단·flags OFF | 금액·자동 기능 즉시 보류, 파일 갱신 실패에도 적용 | 다른 조건·제공 가능 사유·갱신 |
| 네트워크/503 복구 gate | “자료를 확인하지 못했어요”·확인일 미연장 | 다시 시도·내 조건 유지 |
| 위치/알림 거절 | “직접 선택해서 확인할 수 있어요” | 지역/점포 수동 선택. 반복 권한 요청 없음 |
| 보호 저장 실패 | 입력·기존 데이터 유지·저장 성공 표시 없음 | 다시 저장·항목 정리·명시적 취소 |
| 삭제 중/일부 실패 | 중복 방지·삭제 단계별 실제 결과 | 재시도·취소 가능한 시점 안내 |
| 원격 제보 토큰 저장 실패 | 성공/취소 결과 분리, 복구 수단 유지 | 토큰 보호 저장 재시도·명시적 서버 삭제 |

여러 상태가 겹치면 차단/권리 종료→시간/안전 만료→규칙 미지원/자격→계산 결과 순으로 평가한다. 개인정보·안전 실패를 일반 네트워크 retry 한 줄로 숨기지 않는다. safe empty와 unknown을 결제 실패로 표시하지 않는다.

## 11 최소 구현 계약과 소유

공유 계산·카탈로그·의존성·safety 모델은 root 소유다. FE는 이 문서의 화면 상태와 단말 메타데이터를 구현하되 기존 보호 저장의 wallet/rules/conditions/consent/reports를 삭제하거나 재해석하지 않는다. BE는 기존 bootstrap/catalog/reports와 안전 복구 계약을 유지한다. 새 서버 wallet·favorite·recent·payment 테이블과 지갑 업로드 API는 만들지 않는다.

| 모델 | 최소 필드·의미 | 보존/무효화 |
|---|---|---|
| Navigation | activeTab: HOME/EXPLORE/WALLET/SAVED, stack: screen ID와 rule/brand/wallet ref | 메모리, 뒤로 이동 복원. 전체 삭제 후 FIRST |
| CheckDraft | origin: PUBLIC/PERSONAL, 대상/채널/수단 ref, amount text·eligible text, step, 현재 입력 | 메모리만. 새 시작/완료/전체 삭제 때 정리. 오래된 결과 보존 없음 |

schema 확장은 기존 v1 load→필드 기본 빈 목록/미완료 첫 실행 적용→원자 저장이다. migration 실패 시 기존 bank/pointer를 유지하고 재시도한다. 기본 수단 자동 설정이 개인 자격 TRUE를 의미하지 않는다. 검색/뷰 모델은 제공 자료와 개인 자료의 출처를 보존하며 실제 엔진 호출마다 모드를 한 개로 확정한다. UX의 표시 상태는 엔진 Truth/이유 코드·현재 safety의 변환이고 별도 금액 계산이 아니다.

네트워크는 기존 `GET /v1/bootstrap`→불변 catalog 검증/원자 교체, `POST /v1/reports`, token Bearer `DELETE /v1/reports/{id}`만 사용해 P0를 완결한다. 갱신 실패 시 안전 확인 시각을 연장하지 않고 새 차단/OFF를 먼저 저장한다. HTTP INPUT_INVALID/413은 필드·길이 오류, 401은 삭제 자격 실패, 429는 재시도 대기, 503은 실제 접수/삭제 미완료로 매핑한다. 원본문/토큰/SQL을 화면 오류에 복제하지 않는다. 공용 위치·알림 OFF, 무통신 제보 자동 발송 없음, 공식 검수는 실제 HUMAN 원문 증거가 있어야 한다.

About에는 앱 버전·제공 범위·실제 공개 자료 상태·기기 저장/권한의 한계·개인정보/도움말을 둔다. 개발 정보 하위에는 환경·연결 주소·빌드/안전 revision·진단을 둔다. 진단은 개인정보·토큰 없는 요약이다. “예시 체험”은 일반 홈 CTA나 계산 자료 선택 항목에서 빼고 명시적 체험 진입에서만 실행한다. 체험 화면/모든 결과에는 “가상 예시 · 실제 혜택 아님” label을 지속 표시하고 지갑·즐겨찾기·최근·공개 목록을 바꾸지 않는다. production fixture 포함 여부는 root의 빌드 정책으로 검토하며 예시 체험을 실제 혜택 확보로 표현하지 않는다. 웹 저장 방식의 차이는 첫 저장의 짧은 안내와 앱 정보에서 사실대로 설명한다.

## 13 매장 결제와 멤버십 코드 제시 보충

사용자의 추가 우선 과업은 “현재 매장에서 내 지갑의 확인 가능한 혜택 중 유리한 조건을 보고, 사용할 멤버십 바코드/QR을 바로 제시하기”다. 모든 지갑 수단의 후보 비교는 기존 TypeScript 엔진의 적격 결과로 한 카드와 최대 한 멤버십 조합만 평가한다. 자료 0개·UNKNOWN·중복 불명은 비교 근거 없음/확인 필요를 표시하며 최대 할인·실제 적용을 보장하지 않는다. 카드 혜택은 조건과 사용 순서를 안내하고 앱이 카드 결제용 코드를 만들지 않는다.

멤버십 지갑 상세와 계산 결과의 선택 멤버십에서 “코드 제시/코드 추가”로 진입한다. 수동 등록은 QR 최대512 UTF-8바이트, CODE128 출력 가능한 ASCII 최대80자, EAN13 체크 숫자를 포함한13자리다. 사용자가 멤버십 전용임을 확인하고 저장하며 카드 수단에는 등록하지 못한다. 형식 검사만으로 발급사/결제용 여부·현재 유효성을 검증했다고 주장하지 않는다. 카드번호·결제QR·카메라 인식·원격 발급/검증·가짜 발급사 링크는 범위에서 제외한다. 실시간으로 바뀌는 코드는 공식 앱을 이용한다.

코드 값은 wallet 참조·형식·이름·수정일과 함께 native 보호 저장에만 둔다. 서버·로그·제보·URL·분석·즐겨찾기/최근 사본에 코드 값/SVG를 전달하지 않는다. 수정 저장 실패 시 입력과 기존 코드를 유지하고 삭제는 확인 뒤 저장 성공을 반영한다. 수단/단말 전체 삭제가 연결 코드도 정리한다. 제시 화면은 흰 여백·검은 코드·큰 비율 유지·가로 스크롤 없음·선택 가능한 원문 값·뒤로·수정/삭제 확인을 제공한다. 앱이 임의 만료기간을 정하거나 실제 포인트를 자동 조회하지 않음을 설명한다.

추가 인수 기준은 멤버십만 등록, 세 형식 경계/체크 숫자 검증, 실제 local SVG 생성, 보호 저장 후 재실행 보존, 삭제 실패/전체 삭제/지갑 삭제, 계산 결과→선택 멤버십 코드 제시다. 실제 iPhone/Android 화면 밝기·크기와 매장 스캐너 판독은 **미수행**이며 SVG 생성/웹 표시 성공을 실물 스캔 성공으로 기록하지 않는다.
