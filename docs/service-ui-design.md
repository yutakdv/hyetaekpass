# 혜택패스 일상 서비스 UI/UX 설계

2026-09-30 · 새 Goal: “검증판이 아닌 실제 앱 서비스로 쓸 정도의 UI/UX와 세부 기능들까지 구체적으로 기획해서 진행”

이 문서는 기존 계산·자료 안전 정책을 유지하면서 사용자가 일상에서 반복할 과업을 설계한다. 디자인 결정과 구현 인수 기준이며, 화면 구현·기기 사용성·공개 출시 완료 증거가 아니다. 기존 [브랜드 자산과 색상](brand-design.md)을 재사용한다. 서비스 기능과 화면 배치는 이 문서로 구체화하고, 실제 구현·시험 결과는 별도 레저에 기록한다.

## 제품 약속과 이번 구현 범위

사용자는 결제 직전에 가진 카드·멤버십의 조건을 확인하고 사용 순서를 읽는다. 공개 자료가 없을 때도 카드번호 없이 보유 수단과 자신이 확인한 조건을 단말에 저장하고 다시 확인할 수 있다. 앱은 결제·금융 실적 조회·자동 자격 판정을 하지 않는다.

설계 가정은 한국어 성인 사용자, 계정 없는 단말 사용, 한 카드와 최대 한 멤버십, 카드 번호·CVC·금융 로그인 입력 없음이다. 사용자에게 이 가정을 설명할 문구는 “카드 번호 없이, 가진 수단과 조건만 보관해요.”다. 공개 지원 규모나 실제 절감액을 만들어 보여주지 않는다.

| 결정 | 사용자가 얻는 변화 | 인수 기준 |
|---|---|---|
| 홈·탐색·지갑·저장 4탭 | 자주 쓰는 과업으로 바로 이동 | 모든 탭은 한 번 눌러 도달하고 현재 탭을 글자·아이콘·선택 상태로 식별. 설정은 홈 상단 버튼 |
| 결제 전 확인을 독립 단계 화면으로 구성 | 긴 폼 대신 지금 필요한 입력만 진행 | 브랜드·채널·수단·금액 → 해당 조건 → 결과. 이전 단계로 돌아가도 입력 보존 |
| 공개 자료와 내 조건을 탐색에서 분리 | 검수 자료와 사용자 작성 자료 구별 | 결과·상세·저장·검색 어디서든 origin 표시 유지. 두 자료의 조합/합계는 만들지 않음 |
| 내 조건 작성의 친숙한 단위 | 개발 산식 단위 없이 작성 가능 | 정률은 `%`, 정액은 `원`, 기간은 한국 날짜. 저장 시 계약 단위로 정확히 변환 |
| 저장·최근 확인을 로컬 기능으로 제공 | 재방문 시 다시 찾는 수고 감소 | 새 서버 전송 없음. 저장한 ID로 현재 유효 자료를 다시 조회·판정 |
| 개발 상세를 앱 정보로 이동 | 일반 사용자가 구현 설정을 해석할 필요 감소 | 일상 화면에서 API 주소·원시 ID·TTL·basis points·UTC 입력·검증판 배지 제거 |

상태의 의미는 그대로 유지한다. UNKNOWN은 모름이고 합계와 조합 순위에서 제외한다. 실제 공개 원문 검수·이용권이 없는 자료를 검수됨으로 표시하지 않는다. 가상 예시는 설정에서 사용자가 선택해서 열고, 예시를 보는 모든 화면에 “가상 예시 · 실제 상품이 아니에요”를 표시한다. 공개 자동 알림 OFF는 “준비 중” 상태와 이유를 그대로 제공한다.

## 정보 구조와 이동

하단 탭은 **홈 · 탐색 · 지갑 · 저장**이다. 설정은 홈 상단의 이름 있는 기어 버튼으로 열리는 독립 상세 화면이다. “결제 전 확인”은 홈의 가장 큰 행동, 탐색 상세의 행동, 지갑에 연결된 조건의 행동에서 여는 독립 화면이다. 결제 흐름·편집·설정 화면에서는 하단 탭 대신 뒤로·단계 제목·닫기를 제공한다. 탭을 오가며 폼이 화면 아래에 남는 기존 방식은 사용하지 않는다.

```text
홈 ── 이번 결제 확인하기 ── 1. 결제 정보 ── 2. 조건 확인 ── 3. 예상 결과
 │                             ↑ 이전 입력 보존          │
 ├─ 저장한 조건 ── 혜택 상세 ── 이 조건으로 확인          └─ 조건 수정
 └─ 지갑 요약 ── 지갑 ── 등록 / 상세 / 수정 / 삭제

탐색 ── [공개 자료 | 내 조건] ── 검색·필터 ── 혜택 상세
  └─ 내 조건 작성 ── 기본 정보 ── 상세 조건 ── 저장·상세

저장 ── 저장한 조건 / 최근 확인 ── 현재 자료의 혜택 상세

홈 상단 설정 ── 위치·알림 / 자료 상태 / 내 제보 / 개인정보·삭제 / 앱 정보·예시
```

| 진입·이동 | 복귀·보존 규칙 |
|---|---|
| 탐색에서 상세 열기 | 닫으면 검색어·필터·스크롤 위치로 복귀 |
| 홈에서 결제 시작 | 최초는 빈 입력, 같은 실행 중 재진입은 진행 중 입력 복원. “새로 확인”은 명시적으로 초기화 |
| 상세에서 결제 시작 | 해당 자료 모드·브랜드·수단을 미리 선택. 금액·자격은 자동 충족 처리하지 않음 |
| 작성 중 닫기·Android 뒤로 | 입력이 바뀌었다면 “작성 중인 내용이 있어요” / “계속 작성” / “저장하지 않고 닫기” |
| 저장 완료 | 상세 화면으로 이동하고 “내 조건을 저장했어요” 안내. 다른 탭에 편집 폼을 남기지 않음 |
| 금액·수단·브랜드·채널·조건 변경 | 이전 결과를 즉시 숨기고 다시 확인 필요로 전환. 오래된 숫자가 현재 입력 결과처럼 남지 않음 |
| 자료 갱신·차단·월 변경·상품 수정 | 저장한 조건 충족 표시와 결과를 최신 계약으로 재판정. 새 확인이 필요하면 명확히 요청 |
| 전체 단말 삭제 | 진행 중 폼·검색·저장·최근 항목·예시·결과도 초기화. 시작 홈으로 이동 |

## 화면 1: 홈

첫 화면의 우선순위는 **이번 결제 확인 → 내가 보관한 조건 → 지갑 상태**다. 브랜드 로고는 32px 심벌과 서비스명으로 간결하게 사용한다. 매 화면에 소개 문구와 개발 공지를 반복하지 않는다.

```text
[심벌] 혜택패스                           [설정]

결제 전에,
확인할 조건을 또렷하게.
[ 이번 결제 확인하기 → ]
카드·멤버십 조건을 한 단계씩 확인해요.

내가 보관한 조건                         모두 보기 →
[내 조건 · 직접 작성/미검수]
시험 카페 10% 조건
연결 수단 · 매장 · 적용 기간
[조건 보기]          [결제 전 확인]

내 지갑                                  지갑 보기 →
카드 1개 · 멤버십 1개
[ 보유 수단 추가 ]

최근 확인                              전체 지우기
[브랜드·조건 이름] · [직접 작성/공개 자료]

[홈]       [탐색]       [지갑]       [저장]
```

처음 실행은 소개 슬라이드 대신 홈에 한 장의 시작 안내를 보여준다. “가진 수단 하나부터 등록해요” / “상품 이름과 등급만 단말에 보관해요” / “지갑에 추가”가 주 행동이다. 위치·알림 권한을 요청하지 않는다. “둘러보기”는 탐색으로 이동하며 등록을 강요하지 않는다.

공개 자료 0개는 홈을 경고문으로 채우는 대신 한 장의 안내로 알린다. “현재 공개 계산 자료가 없어요. 이용권과 실제 원문 검수를 확인한 자료부터 제공해요.”와 “내 조건 작성”을 제공한다. 결제 시작 시 사용 가능한 내 조건이 없으면 수단 등록 → 조건 작성으로 연결한다. 가상 예시를 추천 혜택이나 실제 브랜드 목록에 채우지 않는다.

홈의 “저장한 조건”은 현재 자료를 조회해 표시한다. 할인 퍼센트가 있어도 “최대 절약”, “절감한 금액” 같은 성과 지표를 만들지 않는다. 대기·만료·차단 자료는 할인액 대신 상태와 상세 행동을 보인다.

## 화면 2: 탐색과 혜택 상세

상단은 제목 “혜택 탐색”, 검색 필드 “브랜드·조건 이름 검색”, 자료 전환 **공개 자료 / 내 조건** 순서다. 그 아래 줄바꿈 가능한 필터 **전체 / 저장한 조건 / 내 지갑에 연결**과 결제 채널을 둔다. 공개 자료에는 유효 범위가 있을 때만 지역·점포 선택과 “근처 찾기”를 제공한다. 위치 OFF 상태에서는 준비 중 이유와 직접 선택을 제공하고 OS 권한을 요청하지 않는다.

정렬 기본은 이름순이다. 실제 위치를 사용자가 요청하고 정밀도·안전 조건이 유효하면 지원 점포의 거리순을 제공한다. 할인 크기나 인기도로 정렬하지 않는다. 사용자 조건이 아직 모르는 자료를 “가장 좋은 혜택”으로 추천하지 않는다.

| 목록 카드의 순서 | 내용 |
|---|---|
| 출처 종류·현재 상태 | “공개 자료 · 원문 검수”, “직접 작성 · 미검수”, “가상 예시”. 만료·안내 중지·조건 확인 필요 텍스트 |
| 제목 | 브랜드/조건 이름, 최대 2줄 강제 잘라내기 없이 높이 확장 |
| 연결 정보 | 카드 또는 멤버십 이름, 매장/온라인/공식 앱, 적용 기간 |
| 다음 행동 | “상세 보기”가 카드의 주 행동. 저장 버튼은 별도 44px 이상 영역 |

카드에는 입력하지 않은 결제액에 대한 할인 예상 숫자를 표시하지 않는다. 사용자 작성 “10% 조건”은 작성한 규칙 제목/설명이며 현재 결제 적용을 확정하는 표시가 아니다.

상세의 읽는 순서는 제목 → origin/안내 상태 → 핵심 조건 → 사용 순서 → 적용 기간·대상·제외 → 출처·확인일 → 행동이다. 주 행동은 “이 조건으로 확인”, 보조 행동은 “저장”이다. 사용자 조건에는 “수정”과 “삭제”를 제공한다. 공개 자료는 공식 링크가 허용된 경우 “공식 조건 확인”, “오류 제보”를 제공한다.

공개 자료 0개는 “현재 공개 계산 자료가 없어요”와 권리·원문 검수 이유, “내 조건 보기”를 표시한다. 내 조건 0개는 “확인해 둔 조건을 보관해요” / “내 조건 작성”이다. 검색 결과 0개는 “일치하는 조건이 없어요” / “검색 지우기” / “필터 초기화”이다. 이 세 빈 상태를 같은 오류 메시지로 처리하지 않는다.

### 저장·최근 확인의 구체 규칙

저장은 현재 mode와 rule ID만 로컬에 보관한다. 할인액·전체 공개 원문·개인 위치를 추가 저장하지 않는다. 공개 자료 ID가 차단·삭제·만료되면 상세 접근과 계산 정책을 현재 카탈로그·안전 상태에서 다시 판정한다. 내려받을 권리가 사라진 원문 내용을 저장 화면에서 복원하지 않는다. 사용할 수 없는 저장 항목은 “자료를 다시 확인해야 해요”와 저장 해제만 제공한다.

최근 확인은 상세를 열거나 확인을 완료한 조건의 origin+ID, 로컬 시각을 최대 10개로 중복 제거해 보관한다. 금액·계산 결과·위치·제보 내용은 넣지 않는다. 예시는 최근 목록에 보관하지 않는다. 전체 지우기와 단말 전체 삭제에 포함한다. 개인 조건이나 보유 수단 삭제는 연결된 저장·최근 항목도 정리한다. 저장은 제보 서버나 분석 서비스에 전송하지 않는다.

## 화면 3: 결제 전 확인

3단계 진행은 고정 숫자보다 “결제 정보 · 조건 확인 · 예상 결과” 제목을 함께 보여준다. 첫 화면 위에 “결제 전 확인”과 뒤로/닫기, 그 아래 현재 단계 제목을 둔다. 화면 아래 “다음”이나 “예상 결과 보기”는 입력 영역과 구별하되 키보드·Safe Area를 피한다. 뒤로 이동은 조건을 초기화하지 않는다.

### 1. 결제 정보

질문은 “어디에서 결제하나요?”다. 자료 모드 선택 → 브랜드 → 점포(필요할 때, “점포 모름” 허용) → 채널 → 수단 → 금액 순으로 배치한다. 홈페이지나 상세에서 명확한 모드·브랜드를 넘겨받으면 그 선택을 접힌 요약 행으로 표시하고 “변경”을 제공한다.

수단 선택은 연결된 지갑 수단만 기본 표시하고 한 카드·최대 한 멤버십을 허용한다. 같은 종류 두 번째 선택은 첫 수단을 교체하며 “한 카드만 선택할 수 있어요”를 설명한다. 미등록 수단은 “지갑에 등록” 행동으로 연결한다. 공개 계산의 상품 버전 모름은 수단 카드에 “상품 버전 확인 필요”를 표시하고 계산 제외 이유를 결과에서 반복한다.

금액 필드는 “결제 금액”, 입력 뒤에 “원”, 도움말 “할인 전 금액을 입력해 주세요”다. 정수 원화, 쉼표 제거, 1원 이상·10억원 이하 검사이며 음수·소수·지수 표기를 받지 않는다. 입력 중에는 원문을 보존하고 완료 후 쉼표를 붙인다. 잘못된 입력은 필드 아래 이유와 포커스 이동을 제공한다. “모름”은 자격/잔여 조건에 제공하고 결제 금액에 대신 적용하지 않는다.

### 2. 필요한 조건만 확인

해당 브랜드·채널·선택 수단에 연결된 규칙의 requiredConditions와 잔여 필요 여부만 보여준다. 다른 브랜드의 조건, 사용하지 않는 상품의 실적, 무관한 품목 금액은 묻지 않는다. 월·규칙 버전이 유효한 입력은 “이번 달에 직접 확인”을 함께 보이며 사용자가 수정할 수 있다. 상품/월/버전 변경 후 이전 TRUE를 재사용하지 않는다.

| 필드 | 입력·설명 |
|---|---|
| 전월 실적 | “조건 충족 / 미충족 / 모름”. 앱이 금융 내역을 조회하지 않는다는 도움말 |
| 멤버십 등급·유형 | 현재 지갑 등급 요약 + “조건 충족 / 미충족 / 모름” |
| 상품 버전 | 현재 지갑 버전 또는 모름. 지갑 수정으로 연결하되 자동 TRUE로 바꾸지 않음 |
| 대상 품목·점포 | 규칙의 지원 범위·제외 요약 뒤 선택. 점포 위치가 인정 증거가 아님 |
| 이번 달 남은 할인 한도 | `원` 정수 또는 “모름”. 0은 소진, 빈 입력은 모름으로 구별 |
| 이번 달 남은 이용 횟수 | `회` 정수 또는 “모름”. 0은 소진 |
| 할인 대상 품목 금액 | ELIGIBLE 산식/최소금액일 때만 노출. 결제 금액 이하, 빈 값은 모름 |

조건을 모른다는 이유로 다음 버튼을 비활성화하지 않는다. “모르는 조건은 예상 합계에 넣지 않아요”를 짧게 설명하고 “예상 결과 보기”를 실행할 수 있다. 빠진 조건을 무조건 충족으로 채우는 “모두 확인” 버튼은 제공하지 않는다. 지갑 등급 이름만으로 실제 자격을 추론하지 않는다.

### 3. 예상 결과와 사용 순서

우선 표시할 내용은 **현재 결과 상태 → 지금 결제액 예상 → 즉시/청구 구분 → 이용 순서 → 확인할 조건**이다. 숫자를 볼 수 있는 결과에서도 “직접 입력한 조건 기준 예상” 또는 “확인한 조건 기준 예상”과 자료 origin을 바로 읽을 수 있어야 한다.

```text
예상 결과
[직접 작성 · 미검수]
직접 입력한 조건 기준이에요.

지금 결제액 예상                 11,000원
즉시 할인 예상                    1,000원
청구 할인 예상                        0원
개인 자격과 매장의 실제 적용은 별도로 확인해 주세요.

결제 전에 이 순서로
1. 공식 조건과 대상 품목 확인
2. 멤버십 제시
3. 선택한 카드로 결제

추가 확인할 조건
모르는 조건 1개 · 해당 혜택은 예상 합계에서 제외했어요.
[조건 확인하기]

계산에 사용한 입력 / 출처·기간       펼치기
[ 조건 수정 ]               [ 공식 조건 확인 ]
```

예시는 설명용이고, 실제 화면의 단계와 숫자는 엔진이 반환한 plan만 사용한다. 사용자 직접 작성 자료의 카드·멤버십 중복 합산은 제공하지 않는다. 청구 할인은 지금 결제액에서 빼지 않는다. 결과에 totalWon을 큰 “총 할인”으로 새로 노출하지 않는다.

유효한 plan이 없으면 큰 숫자 대신 “확인할 조건이 남아 있어요”, “입력한 조건에서는 계산 대상이 아니에요”, “최신 자료 확인이 필요해요” 중 실제 사유를 표시한다. UNKNOWN을 0원으로 표시하지 않는다. 엔진의 각 규칙 이유를 “확인 필요 / 미충족 / 자료 제한”으로 읽기 쉽게 풀되 원래 상태를 바꾸지 않는다. “조건 수정”은 정확한 해당 단계로 돌아간다. GUIDE_ONLY는 공식 경로와 미지원 이유를 보여주며 숫자를 만들지 않는다.

결제 결과를 앱에서 실제 결제 완료나 잔여 한도 차감으로 자동 처리하지 않는다. 사용자가 앱을 열었다는 사실을 소비·방문·할인 적용 증거로 삼지 않는다.

## 화면 4: 지갑과 보유 수단

지갑은 목록 → 상세 → 편집 구조다. 카드형 리스트에는 상품 이름, 카드/멤버십 종류, 현재 등급, “상품 버전 모름” 여부만 표시한다. 타사 실물 카드 이미지나 로고를 권리 없이 넣지 않는다. 녹색·라임의 직접 만든 심벌과 텍스트로 통일한다. 첫 보유 수단 등록은 1분 내 끝나는 작은 폼을 목표로 하고 실제 시간은 시험 후 기록한다.

등록 화면은 수단 종류, 상품 이름, 등급·유형(모름 허용), 상품/발급 버전(모름 허용)으로 제한한다. 허가된 공개 상품이 있을 때만 검색 선택을 제공한다. 동일 공개 상품은 중복 등록을 막고 기존 수정으로 연결한다. 자유 이름을 입력해 만든 항목은 실제 공개 상품과 일치하는 것으로 자동 매핑하지 않는다.

지갑 상세에는 연결된 내 조건 목록과 “조건 추가”, “상품 정보 수정”을 둔다. 수정 시 상품 버전·등급·종류가 바뀌면 “이 수단의 적용 조건을 다시 확인해 주세요”를 설명하고 연결된 이전 조건 확인을 무효화한다. 저장 오류가 나면 편집 값은 화면에 남고 목록은 이전 정상 값을 유지한다.

삭제는 목록마다 위험색 버튼을 항상 보이기보다 상세의 별도 행동으로 제공한다. 확인 대화상자에 “이 수단과 연결된 직접 작성 조건 N개를 삭제해요”와 “취소 / 삭제”를 표시한다. 실제 삭제 범위가 계산되기 전에 숫자를 임의로 표시하지 않는다. 삭제 후 선택 수단·조건·저장·최근 항목을 정리하고 지갑 목록으로 돌아간다.

## 내 조건 작성·수정

사용자 작성은 “내가 확인한 조건을 보관”하는 기능이다. 작성 완료를 “검수”나 “승인”으로 표현하지 않는다. 폼 머리와 상세·목록·결과에는 “직접 작성 · 미검수”를 유지한다. 공개 카탈로그 import·게시·AI 후보 생성과 연결하지 않는다.

| 단계 | 입력 |
|---|---|
| 기본 정보 | 조건 제목, 브랜드 이름, 연결 지갑 수단, 매장/온라인/공식 앱, 확인할 HTTPS 링크(선택) |
| 할인 정보 | 정률 `%` 또는 정액 `원`, 건당 할인 상한 `원`, 최소 결제 금액 `원`, 즉시/청구 할인 |
| 상세 조건 | 시작일·종료일, 할인 기준금액(원 결제금액/대상 품목), 원 미만 버림/반올림/올림, 사용 순서·제외 조건 |
| 저장 전 확인 | 작성한 주요 조건 요약과 “실제 원문 검수 자료가 아니에요. 잔여 한도·자격은 계산할 때 확인해요.” |

정률은 “10%”처럼 입력하고 소수점 둘째 자리까지 허용하며 정확한 정수 basis points로 변환한다. 100% 초과·음수·NaN·세 자리 소수는 필드 오류다. basis points를 일반 UI에 쓰지 않는다. 건당 상한은 산식의 capWon이며 월 잔여 한도와 별개라는 도움말을 둔다. 모르는 상한·반올림·적용 기간을 할인 계산 규칙으로 임의 확정하지 않는다. 이번 계산형 작성에서 상한·기간·반올림을 확인하지 못했으면 해당 필드에 “계산 조건을 확인해 주세요”를 표시하고 작성 내용을 보존한다. 임의의 무제한 상한·30일 기간을 넣어 계산형 저장을 성공시키지 않는다.

날짜는 “2026-09-30” 같은 익숙한 날짜로 받는다. 날짜 전체 기간을 사용하는 새 조건은 Asia/Seoul 자정 기준 시작, 선택 종료일 다음 날 자정을 exclusive endsAt으로 변환한다. 입력에는 “종료일 포함”을 쓰고 상세에는 실제 한국 시각 적용 기간을 표시한다. 기존 시간 단위 조건을 편집할 때 시간값을 자동 자정으로 잘라내지 않는다. 시간 단위 값은 추가 상세 입력에 한국 시각으로 제공한다. UTC RFC3339는 저장 계약이며 사용자의 기본 입력 방식이 아니다.

현재 엔진이 처리하는 정률·정액 외 산식, 천 원당·포인트·복잡한 조합을 정률로 바꿔 입력하도록 유도하지 않는다. 소스·조건을 수정하면 version을 바꾸고 이전 확인 값을 무효화한다. 조건 삭제는 확인 후 연결된 로컬 메타데이터·저장·최근 항목을 정리한다.

## 화면 5: 저장

저장 탭은 **저장한 조건 / 최근 확인** 두 목록을 제공한다. 검색·현재 자료 origin·상태는 탐색과 같은 카드로 유지한다. 사용자는 조건 상세를 열고 현재 자격·금액을 다시 입력하며, 이전 계산 금액을 결과처럼 재사용하지 않는다. 개별 저장 해제는 별도 44px 영역에서 실행한다. 최근 목록의 “전체 지우기”는 최근 참조만 정리하며 지갑·개인 조건·저장 목록은 삭제하지 않는다.

저장한 항목이 없으면 “다시 볼 조건을 저장해요” / “조건의 저장 버튼을 누르면 여기에서 찾을 수 있어요” / “혜택 탐색”이다. 최근 목록이 없으면 “최근에 확인한 조건이 없어요” / “결제 전 확인이나 혜택 상세를 열면 여기에 남아요”다. 사용할 수 없게 된 공개 참조는 할인 내용 없이 “자료 확인 필요”와 “저장 해제”를 제공한다. 개인 조건 수정은 같은 rule ID의 최신 version을 연결하고 이전 조건 확인은 다시 받는다.

## 화면 6: 설정과 오류 제보

설정 첫 화면은 긴 양식 대신 목록이다. “위치·알림”, “자료 상태”, “내 제보”, “내 정보와 삭제”, “앱 정보” 다섯 그룹의 제목·현재 상태·상세 이동을 제공한다. 각각의 상세에서 설명·선택·행동을 보여준다.

| 그룹 | 일반 UI | 상세·개발 정보 |
|---|---|---|
| 위치·알림 | “주변 자동 알림 준비 중”, “위치 없이 직접 선택 가능” | 목적 동의·OS 권한 별도, 철회, OS 설정. OFF 이유·일 2회·야간 제한. 활성화 가능한 토글처럼 표시하지 않음 |
| 자료 상태 | 마지막 정상 확인 시각, 현재 사용 가능/갱신 필요, “자료 갱신” | 원문/혜택/이용권/안전 기한 중 실제 적용 기한과 중단 사유. 개발 revision·raw flags는 앱 정보로 이동 |
| 내 제보 | 제보 ID의 짧은 표시·제출일·삭제 행동 | 토큰은 기본 접고 “삭제 토큰 보기”로 명시적으로 열기. 화면/로그/최근 항목에 자동 노출하지 않음 |
| 내 정보와 삭제 | 단말 보관·서버에 가는 항목 요약, 전체 삭제 | 실제 삭제 범위·제보 별도 처리·일부 실패 안내. 단말 삭제는 오프라인에도 먼저 수행 |
| 앱 정보 | 서비스 설명·앱 버전·지원 범위·개인정보 안내 | 예시 체험 진입, 내부 빌드일 때 API 주소·schema/revision·플랫폼 flag·진단 상세 |

오류 제보는 혜택 상세에서 진입하면 해당 규칙 참조를 내부 첨부하고 사용자에게 제목을 보여준다. 일반 설정에서 진입하면 규칙 ID를 요구하지 않고 선택 사항으로 숨긴다. “조건 오류 / 기간·차단 / 점포 오류 / 기타” 선택과 비개인 설명, 2,000자 제한을 제공한다. 카드번호·이름·연락처·좌표·거래내역을 넣지 말라는 안내는 작성 필드 바로 위에 둔다. 지갑·현재 위치·계산 입력을 자동 첨부하지 않는다.

전송 중 버튼은 “제보 보내는 중”이며 중복 전송을 막는다. 토큰 저장 실패는 전송 성공으로 끝내지 않고 취소 요청·토큰 보관·재시도 경로를 유지한다. 정상 성공은 “제보를 보냈어요. 설정의 내 제보에서 삭제할 수 있어요.”다. 서버 처리 상태 조회를 구현하지 않았으면 “답변 대기”, “검토 중”, “해결 완료” 같은 상태를 만들지 않는다.

단말 전체 삭제는 위험색 상세 행동, 삭제 범위 안내, 두 번째 확인으로 실행한다. 연결 실패가 단말 데이터 삭제를 막지 않는다. 실제 서버 제보 삭제가 남으면 완료된 단말 삭제와 실패한 서버 삭제를 따로 알리고 필요한 토큰을 보관할 경로를 제공한다.

| 상태 | 문구 | 주 행동·표시 정책 |
|---|---|---|
| 저장소 초기화 중 | “내 정보를 불러오고 있어요” | 입력 잠깐 대기. 실패 시 “다시 확인” |
| 자료 갱신 중 | “최신 혜택 자료를 확인하고 있어요” | 지갑·내 조건 탐색 유지. 새 공개 계산은 유효 상태에 한해 |
| 갱신 실패·이전 기한 유효 | “연결이 끊겼어요. 마지막으로 확인한 자료를 사용해요” | 새 차단을 확인하지 못한 이유·실제 남은 기한. “다시 시도” |
| 안전 기한 초과·시각 불확실 | “최신 상태 확인이 필요해요” | 공개 금액·자동 알림 보류. “자료 갱신”; 지갑·내 조건 사용 유지 |
| 원문·권리·혜택 기간 만료 | “이 자료의 사용 기한이 지났어요” | 새 금액 없음, 다른 조건 탐색. 권리 없는 원문은 복원하지 않음 |
| 차단/OFF | “현재 이 혜택의 안내를 중지했어요” | 금액 없음, 허용된 사유·다른 조건 보기 |
| UNKNOWN | “확인할 조건이 남아 있어요” | 이유별 목록·정확한 조건 수정. 0원으로 변환 없음 |
| FALSE | “입력한 조건에서는 계산 대상이 아니에요” | 미충족 이유·조건 수정 |
| GUIDE_ONLY | “이 혜택은 안내만 제공해요” | 미지원 산식 이유·허용 공식 경로 |
| 보유 상품 버전 모름 | “상품 버전을 확인해 주세요” | 공개 계산 제외, 지갑 수정 연결 |
| 위치 거절·정밀도 부족 | “지역과 점포를 직접 선택해 주세요” | 직접 선택 유지, 반복 권한 요청 없음 |
| 예시 사용 | “가상 예시 · 실제 상품이 아니에요” | 모든 예시 화면 상시 표시. 예시 닫으면 기존 공개/개인 화면 복귀 |
| 저장 실패 | “저장하지 못했어요. 다시 시도해 주세요” | 작성 내용 유지, 이전 정상 저장 자료 보존 |
| 일부 삭제 실패 | “일부 항목을 삭제하지 못했어요” | 실제 실패 범위·다시 시도. 성공처럼 시작 상태를 꾸미지 않음 |

연결 오류의 원시 네트워크 문자열·stack은 앱 정보의 내부 진단으로 옮기고 일상 화면에는 행동 가능한 한국어 이유를 제공한다. 단, 권리·검수·기한·차단 같은 실제 제한 이유를 일반 연결 오류로 바꾸지 않는다.

## 화면 토큰과 상호작용

기존 `brand #086653`, `accent #DFF584`, `background #F6F8F3`, white surface, `text #192D26`, `muted #52635A`를 사용한다. 라임은 홈 소개 영역과 작은 강조 배경에만 사용한다. 위험·모름·안내는 각각 기존 error/warning/info 색상과 반드시 텍스트를 함께 둔다. 새 UI 프레임워크·카드 이미지·폰트·아이콘 의존성은 필요하지 않다.

| 토큰 | 기본값·규칙 |
|---|---|
| 화면 여백 | 좌우 20px, 320px에서는 16px. 최대 콘텐츠 너비 700px, 세로 흐름 |
| 카드 | 안쪽 16~20px, 모서리 18px, 얇은 경계. 고정 높이 없음 |
| 간격 | 관련 필드 12px, 묶음 20px, 섹션 28px. 주요 버튼 사이 8px 이상 |
| 글자 | 제목 28/36px, 섹션 21/29px, 본문 17/26px, 보조 14/21px. 시스템 글꼴·사용자 확대 유지 |
| 주 버튼 | 최소 높이 52px, 내용에 따라 높이 확장. 녹색·흰 글자 |
| 보조 버튼 | 최소 48px, white surface·명확한 경계. 한 화면의 큰 주 행동 하나 |
| 터치 | 모든 아이콘·뒤로·저장·닫기 최소 44×44px. 작은 텍스트라도 실제 hit 영역 확보 |
| 하단 탭 | 4등분, 짧은 이름·선택 상태. Safe Area 추가. 200% 글씨에서 2줄/높이 확장 |
| 금액 | 지금 결제액 예상 30/40px, 다른 금액 22/30px. 의미+원 단위 한 읽기 묶음, 세로 행 |
| 포커스 | 웹 키보드에 브랜드색 3px focus 외곽. 상태는 색 외 제목·이유·행동 |

혜택 상세·편집은 화면 전체를 사용한다. 작은 확인 대화상자만 모달을 사용한다. 긴 폼을 낮은 고정 높이 bottom sheet에 넣지 않는다. 시트가 필요하면 전체 높이까지 확장·스크롤하며 모든 내용을 읽을 수 있어야 한다. 저장/삭제/진행 버튼은 OS 홈 표시·키보드에 가리지 않는다.

## 접근성·작은 화면 인수 기준

1. 320px에서 본문·칩·입력·결과·탭이 가로 스크롤 없이 보여야 한다. 필터는 줄바꿈하고 조건 선택은 필요하면 세로 세 행으로 전환한다. 200% 확대에서도 본문 줄 수 제한·고정 카드 높이·금액 잘림이 없어야 한다.
2. 모든 Text에 사용자 글자 확대를 허용한다. 입력 레이블은 placeholder와 별도로 항상 보이고 단위·필드 오류를 연결한다. 영어 개발 단위만으로 입력을 요구하지 않는다.
3. 접근성 순서는 화면 제목 → 자료/현재 단계 상태 → 입력 또는 결과 → 도움말 → 행동이다. 예시 origin과 UNKNOWN·만료 상태를 screen reader에도 제공한다.
4. 탭은 선택 상태, 수단 선택은 체크 상태, 세 가지 진실값은 현재 선택과 완전한 한국어 이름을 제공한다. 아이콘만 있는 저장은 “조건 이름 저장/저장 해제”, 닫기는 “결제 전 확인 닫기”로 읽는다.
5. 모달은 열릴 때 제목으로 초점, 외부 내용 접근 제한, 닫힐 때 원래 버튼으로 복귀한다. 웹 Escape와 Android 뒤로가 취소로 작동한다. 위험한 삭제를 기본 자동 실행하지 않는다.
6. 단계 이동·저장·실패는 짧게 알리고 매 초 시각·로딩 애니메이션을 반복 낭독하지 않는다. 입력 오류는 첫 오류로 스크롤·초점 이동하며 값을 보존한다.
7. 숫자 키보드가 열린 iOS/Android에서 완료/다음 행동을 누를 수 있어야 한다. 화면 회전이나 뒤로 이동 때문에 입력이 사라지지 않는다. 키보드가 입력과 오류를 가리지 않는다.
8. 금액은 “지금 결제액 예상, 만 천 원”처럼 의미와 단위를 함께 읽는다. 0원은 실제 확인된 0원일 때만 표시한다. UNKNOWN에 숫자·퍼센트만 남는 상태가 없어야 한다.
9. 웹 화면의 키보드·320px·큰 글씨 확인은 실제 native VoiceOver/TalkBack·글자 확대·Safe Area·키보드 시험과 구별해 기록한다.

## 구현 순서와 확인해야 할 과업

첫 구현은 4탭 shell·홈·탐색·지갑 상세/독립 편집을 연결한다. 다음은 3단계 결제와 결과·내 조건 친숙한 입력, 그 다음 저장 탭·로컬 최근·설정의 정보 구조·제보/삭제 상세다. 계산 엔진·자료 권한·단말 처리 경계를 수정하는 우회 구현은 하지 않는다.

| 실제 확인 과업 | 완료 증거 |
|---|---|
| 공개 자료 0개 첫 실행 → 지갑 등록 → 내 조건 작성 → 결과 | 화면 입력·보호 저장·재실행 보존·실제 엔진 결과 |
| 개인 조건 정률 10% 저장 → 내부 value 1000, 기간 KST 변환 | 단위/날짜 경계 검사와 실제 작성 UI |
| 검색·필터·저장 → 상세 → 복귀 | 검색/필터 보존, 중복 저장 없음, 재실행 목록 |
| 결제 단계 뒤로 → 수단/금액 수정 → 다시 결과 | 입력 보존·이전 결과 즉시 숨김·필요 조건만 노출 |
| 모름·미충족·상품 버전 모름·잔여 0 | 이유별 상태, UNKNOWN 합계 제외, 숫자 보류 |
| 원문/권리/안전 만료·차단·갱신 실패 | 동일한 계산 안전 회귀 통과·UI 제한 사유 유지 |
| 보유 수단 수정·삭제 | 이전 자격 무효화, 연결 조건/저장/최근 정리, 삭제 범위 확인 |
| 제보 작성·토큰 보관 실패·삭제·단말 오프라인 삭제 | 민감 자동 첨부 없음, 실제 API·DB·로컬 삭제 결과 |
| 설정에서 예시 진입·종료 | 모든 예시 화면 origin 표시, 일반 자료와 결과/저장 분리 |
| 320px·200%·키보드·Safe Area·VoiceOver/TalkBack | 실제 환경별 화면·실행 기록. 미시험 항목은 대기로 남김 |

화면을 서비스답게 만드는 것과 공개 데이터·법률·운영 인증·서명·스토어·실물 기기 검증은 각각의 완료 조건이다. UI 정리 때문에 외부 준비가 해결됐다고 기록하지 않는다. 실제 사용자에게 설명 가능한 안전 상태를 유지하며 기능과 구현 검증을 계속한다.
