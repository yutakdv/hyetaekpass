# 혜택패스 브랜드와 모바일 디자인

2026-09-30 · 디자이너 산출물 · 제품 문서의 초기 검증판 범위에 맞춘 최종 디자인안

## 이름과 약속

최종 서비스명은 **혜택패스**, 영문 표기는 **Hyetaekpass**다. 저장소·식별자에는 기존 `hyetaekpass`를 유지한다. 소개 문구는 **“결제 전에, 조건을 또렷하게.”**, 한 문장 설명은 “내 카드·멤버십의 조건과 사용 순서를 결제 전에 확인해요.”다.

| 검토한 이름 | 판단 |
|---|---|
| 혜택패스 / Hyetaekpass | 혜택이라는 과업이 바로 읽히고 카드·멤버십을 함께 담는다. 기존 프로젝트와 일치해 선정 |
| 혜택노트 | 개인 메모에 치우쳐 검수된 자료·주변 탐색까지 설명하기 어렵다 |
| 결제전 | 결제 시점을 강조하지만 서비스가 결제를 처리하는 것으로 오해할 수 있다 |

이름은 제품 디자인상의 선정이다. 2026-09-30 검색엔진에서 정확한 이름으로 [KIPRIS](https://www.kipris.or.kr), [Apple App Store](https://apps.apple.com), [Google Play](https://play.google.com) 도메인 대상 검색을 했으나 결과가 반환되지 않았다. 이는 각 서비스 내부 검색이나 상표 선행조사를 완료한 결과가 아니며, 동일·유사 명칭 부재, 사용권, 등록 가능성, 상표권 확보를 뜻하지 않는다. 공개 전에 실제 주체가 지정상품·유사 표장까지 확인해야 한다.

“최대 할인 보장”, “전국 모든 혜택”, “입장 감지”, “2분 뒤 반드시 알림”을 제품 문구로 사용하지 않는다. “검수”는 자료 원문 검수를 뜻하며 실제 결제 적용이나 개인 자격 확인과 구별한다.

## 로고와 자산

**열린 패스**를 최종 심벌로 선정했다. 양쪽 홈이 있는 패스 안의 H는 보유 수단과 확인 정보를 잇는 형태다. 원화·퍼센트·체크마크 없이 혜택 확인을 표현해 할인 보장을 암시하지 않는다. 둥근 모서리와 하나의 덩어리는 작은 앱 아이콘에서도 구별하기 쉽다. 모든 형태와 한글 레터링은 직접 작성한 SVG 도형·경로다. 외부 로고, 카드 이미지, 폰트 파일을 반입하지 않았다.

| 자산 | 용도 |
|---|---|
| `assets/brand/logo.svg` | 한글 로고. 원본 경로형 레터링이므로 별도 폰트 설치 없이 렌더링 |
| `assets/brand/symbol.svg` | 단색 심벌. `currentColor`, 투명 여백, 100 × 100 viewBox |
| `assets/brand/symbol-1024.png` | 투명 배경 심벌 PNG. 이미지 기반 UI·미리보기 |
| `assets/brand/app-icon.svg` | 앱 아이콘 원본. 플랫폼 마스크를 적용하기 전의 전체 정사각형 |
| `assets/brand/app-icon-1024.png` | 1024 × 1024 불투명 앱 아이콘. 네이티브 프로젝트가 필요한 해상도·플랫폼 자산으로 변환 |
| `assets/brand/showcase.html` | 외부 네트워크 없이 보는 로고 6안·최종 아이콘·상태·모바일 구성 비교 |
| `assets/brand/variants/01-pass.svg` … `06-fold.svg` | 비교한 여섯 방향. 01만 제품에 적용 |

6안 검토: 01 열린 패스는 단일 형태와 H의 식별성이 좋아 선정했다. 02 펼친 지갑은 로컬 보유 수단을 잘 설명하나 금융 지갑 서비스 인상이 강하다. 03 가까운 발견은 위치 기능을 핵심 약속으로 오해하기 쉽다. 04 연결된 카드는 조합을 설명하지만 중복 허용을 미리 암시할 수 있다. 05 혜택 모듈은 모듈형 정보와 H를 연결하지만 작은 크기의 간격이 약하다. 06 접힌 패스는 메모와 북마크에 가깝다.

로고 주변은 심벌 높이의 1/4 이상 비운다. 심벌 권장 표시 크기는 32px 이상, 최소 24px이다. 한글 로고는 가로 160px 이상에서 사용하고 더 작은 곳은 심벌과 시스템 글꼴의 이름을 쓴다. 심벌을 늘이거나 회전하거나 타사 카드 로고처럼 표시하지 않는다. 앱 아이콘에는 글자를 추가하지 않는다. 실제 iOS·Android 마스크·런처·빌드 적용 검증은 FE 담당의 별도 완료 항목이다.

일반 본문과 필수 보조문구는 대비 4.5:1 이상, 입력·포커스·상태 경계는 3:1 이상을 목표로 한다. 브랜드 버튼은 흰 글자, 라임 배경은 text 글자만 쓴다. 상태에는 “조건 확인 필요”와 같은 텍스트를 항상 붙인다. 색만으로 검수·가능·오류를 구분하지 않는다. 미지원 항목도 이유와 대체 경로를 읽을 수 있게 한다.

시스템 글꼴을 사용한다. iOS와 Android의 한국어 기본 글꼴 및 사용자의 글자 크기를 따른다. 본문 17/26px, 보조 14/21px, 화면 제목 28/36px, 섹션 22/30px, 금액 28/36px를 시작값으로 한다. 설명과 금액을 이미지에 넣지 않는다. 200% 글자 크기에서 텍스트를 잘라내거나 줄 수를 강제하지 않는다. 큰 금액은 숫자와 원 단위를 함께 줄바꿈할 수 있는 별도 행에 둔다.

## 화면 구조와 흐름

하단 이동은 **혜택 · 내 지갑 · 설정** 세 곳으로 제한한다. 혜택 화면 안에서 “근처 목록”을 요청할 수 있다. 상단에는 로고·서비스명과 “검증판”을 표시한다. 개발·시험 데이터가 켜진 빌드는 “개발용 가상 자료 · 실제 상품이 아님”을 상시 표시하고 운영 자료와 섞지 않는다.

| 화면 | 정보 우선순위와 행동 |
|---|---|
| 첫 실행·지원 범위 | 실제 지원 생활권·브랜드·상품·자료 확인일 → 공개 자료 상태 → “지원 상품 보기”, “내 지갑”. 권한을 즉시 요청하지 않음 |
| 내 지갑 | 보유 수단 목록 → 하나부터 등록·수정. 상품·버전·멤버십 등급·유형을 선택하고 “모름” 허용. 카드 번호·CVC·금융 로그인 입력란 없음 |
| 혜택 선택 | 생활권·브랜드 → 점포 → 결제 채널 → 보유 수단. 위치 없이 모든 단계 직접 선택 가능 |
| 조건 입력 | 결제 금액 → 해당 규칙에 필요한 실적·잔여·등급·품목 등만 묻기. “충족 / 미충족 / 모름”을 동등한 선택으로 표시 |
| 결과 | 자료 상태 → 먼저 해야 할 사용 순서 → 확인한 조건 기준 예상 → 미확인 조건 → 출처·확인일·적용 기간 → 공식 웹 확인·오류 제보 |
| 주변 목록 | 사용자가 직접 요청 → 위치 목적 설명 → 권한 요청 → 단말 거리순 후보. 점포 위치를 할인 적용 증거로 표시하지 않음 |
| 설정 | 위치·알림 설정과 각각의 동의 → 카탈로그 갱신 상태 → 제출한 제보 삭제 방법 → 단말 전체 삭제 |
| 제보 | 규칙·사유·비개인 설명 → 민감정보 입력 금지 안내 → 제출 → 삭제 토큰 보관 안내·제보 삭제 |

예상 결과는 세 줄을 독립 표시한다: **즉시 할인 예상**, **지금 결제액 예상**, **청구 할인 예상**. 청구 할인을 지금 결제액에서 빼거나 합계 한 숫자로 강조하지 않는다. 숫자가 없는 이유도 표시한다. UNKNOWN을 0원·미충족으로 바꾸지 않는다. 사용자 입력값을 서버가 자동 확인한 것처럼 표현하지 않는다. 화면 예시는 가상 12,000원 → 즉시 1,000원 → 지금 11,000원 → 청구 550원으로, 중복·순서·기준금액이 확인된 경우에만 세 번째 숫자가 나온다.

계산 버튼은 입력 형식이 잘못되면 필드 오류로 연결한다. 모름 자체는 저장·탐색을 막는 입력 오류가 아니다. 공개 가능한 규칙이 0개여도 지갑·직접 선택·설정·허용된 사용자 직접 작성 기능은 정상 동작한다. 이 상태에 가상 할인이나 추천 순위를 채우지 않는다.

화면 좌우 여백 20px, 카드 내부 20px, 카드 간격 12px, 주요 영역 간격 24px, 모서리 16px를 시작값으로 쓴다. 필요한 버튼 경계에는 controlBorder를 사용한다. 고정 높이 카드·가로 스크롤 조건 입력·과도한 그림자·계산 순위를 암시하는 금색 배지를 추가하지 않는다.

주변 알림 기본 문구는 “근처에서 확인할 수 있는 혜택이 있어요”다. 잠금화면에 카드·멤버십명, 실적, 좌표, 금액을 넣지 않는다. 광고 분류에 필요한 발신자·연락처·수신 거부 표시는 실제 법률 확인 후 반영하고, 해당 확인이 없는 공개 자동 기능은 OFF로 유지한다. 야간 21:00~08:00에 밀린 위치 알림을 다음 아침으로 넘기지 않는다.

## 접근성과 검증 책임

- 320px 작은 화면과 200% 글자 크기에서 단일 세로 흐름을 유지한다. 고정 가로 칩은 여러 줄로, 금액 요약은 세로로 바뀐다. Safe Area와 키보드에 주요 행동이 가리지 않도록 한다.
- 모든 터치 영역은 최소 44 × 44px이고, 기본 버튼·선택 행은 48px 이상이다. 버튼 사이에는 최소 8px 간격을 둔다.
- 스크린리더 순서는 제목 → 자료 상태 → 사용 순서 → 예상 결과 → 미확인 조건 → 출처 → 행동이다. SVG title만 의존하지 않고 모바일 Image에 접근성 레이블을 제공한다. 인접한 서비스명 텍스트가 읽히면 심벌은 장식으로 제외한다.
- 금액은 “지금 결제액 예상, 만 천 원”처럼 의미와 단위를 읽는다. 원문 검수와 사용자 적용 확인을 같은 접근성 이름으로 묶지 않는다. 조건 선택에는 selected 상태, 토글에는 checked 상태를 제공한다.
- 오류 메시지를 입력과 연결하고 오류 발생·갱신 완료를 짧게 안내한다. 로딩 애니메이션 반복 낭독을 피한다. 웹 관리 화면은 키보드·명확한 focus 표시를 지원한다.
- UI 상태·로고·색상 검사는 디자인 산출물의 검증이다. VoiceOver·TalkBack, 양 OS 큰 글씨·삭제·권한·실제 빌드 검증은 FE 통합 후 실제 기기에서 기록한다. 디자인 문서만으로 이를 통과 처리하지 않는다.

## 실제 확인 결과

2026-09-30 저장소 안의 자산을 bundled Sharp로 PNG 변환하고 Python 표준 XML 파서로 확인했다. 새 의존성·외부 이미지 API를 추가하지 않았다.

HTML 브라우저 실행 검증은 수행하지 못했다. bundled Playwright의 브라우저 실행 파일이 없고, 로컬 서버 bind는 sandbox에서 제한되었으며, CUA는 `file:` URL을 보안 정책으로 차단했다. 우회하지 않았다. 따라서 320px·큰 글씨의 실제 렌더링, 비교 선택 동작, 스크린리더, 실제 양 OS 마스크·런처·빌드 적용은 통과로 표시하지 않는다. FE 통합에서 별도로 확인해야 한다.
