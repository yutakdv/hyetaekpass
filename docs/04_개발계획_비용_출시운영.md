# 혜택패스 개발 공수와 비용 출시 운영

기준일은 2026년 9월 30일이다. 개발자별 주당 시간이 아직 정해지지 않았으므로 **출시 날짜를 확정하지 않고 팀 공수와 가용시간으로 일정을 계산한다.** Android와 iOS의 기본 기능을 함께 개발하고 현재 iPhone으로 실기기 검증을 먼저 진행한다. AWS 운영 완료와 스토어 공개 승인은 서로 다른 완료 조건이다.

## 1 단계와 완료 조건

| 단계 | 결과물 | 다음 단계로 넘어갈 조건 |
|---|---|---|
| 가정 확인 | 두 OS 작은 빌드, iPhone 위치 관측, 이용 가능한 데이터 10건, 사용자 과업 | 데이터·권한·기기·운영 시간이 현실적인지 확인 |
| 핵심 검증판 | 로컬 지갑, 수동 검색, 조건부 예상, 출처, 삭제, 소량 운영 카탈로그 | 필수 계산 사례 전부 통과, 실제 사용자가 혜택과 미확인 조건을 이해 |
| 전경 주변 기능 | 생활권 점포와 거리순 목록, 목적별 권한 설명 | 위치 관련 절차·권리·거절 UX, 양 OS 실기기 확인 |
| 백그라운드 파일럿 | 플랫폼별 선택형 알림과 장소 제외 정책 | 실행 기회·지연·오탐·배터리·동의·스토어 정책 검증 |
| AWS 검증 운영 | HTTPS API, 제한 DB, 게시·차단·복구, 비용 관측 | 실제 복구 훈련과 데이터 갱신·제보 처리 가능 |
| 공개 출시 | 각 스토어 승인과 단계 배포 | 플랫폼별 증거 충족. 실패한 자동 기능을 활성화하지 않음 |

위치는 사용자가 원하는 핵심이므로 기술 확인을 초반에 한다. 다만 백그라운드가 실패해도 공개 출시 날짜를 맞추려고 방문 감지 성능을 과장하지 않는다. 전경·수동 제품만으로 사용가치가 남는지 다시 판단한다.

## 2 팀 공수의 시작 추정

다음은 신규 구축을 위한 검토용 추정이다. 실제 작업 기록이나 팀 생산성 측정치가 아니다. 좁은 생활권, 10~20개 연구 후보, 소량 허가 데이터, 계정 없음, 무료 검증판, 기존 기술의 기본 경험을 가정한다. 계약 회신·기관 상담·스토어 대기·외부 구매 기간은 작업시간 밖의 일정 의존조건이다.

| 작업 | 팀 합계 시간 |
|---|---:|
| 범위 확정과 양 OS 개발 도구·작은 빌드 | 40~60시간 |
| 데이터 확보 준비·구조화·실제 검수·계산 사례 | 60~90시간 |
| 모바일 지갑·검색·계산·조건 설명·전체 삭제·접근성 | 180~240시간 |
| BE와 작은 관리 화면·릴리스·차단·제보 | 160~220시간 |
| 전경 주변 목록과 권한·미확인 처리 | 50~70시간 |
| Docker·AWS·배포·보안 경계·백업 복구 | 100~130시간 |
| 양 OS QA·사용자 과업·스토어 준비·수정 | 160~220시간 |
| 개발·운영 문서와 인수 가능한 복구 절차 | 50~70시간 |
| 핵심 및 전경 기능 합계 | **800~1,100시간** |
| 선택형 백그라운드 기능 추가 | **200~400시간 추가** |

백그라운드 추가 공수에는 초반 40~80시간의 가능성 시험, OS별 연결·동의·상태 처리, 현장 시험과 튜닝을 포함한다. 처음부터 120초 타이머로 해결됐다고 보고 이 공수를 제거하지 않는다. 반복 반려·네이티브 학습·많은 기기·복잡한 규칙·유료화가 생기면 다시 산정한다.

두 명이면 일을 나눌 수 있지만 앱·계산·데이터·검수에는 의존관계가 있다. 한 명이 원문 작성과 독립 검수를 동시에 수행할 수 없다. 시간 합계만으로 병렬성이 무한하다고 계산하지 않는다.

## 3 주당 시간별 일정

작업 가능량은 `개발자 수 × 1인 주당 가용시간 × 0.70`으로 시작한다. 나머지 30%는 자료 갱신·제보·회의·돌발 수정·짧은 부재의 여유다. 데이터 정기 운영 시간을 다시 공수 합계에 중복 더하지 않는다. 실제 운영이 이 여유를 넘으면 개발 범위를 줄인다.

| 인원과 1인 가용시간 | 계획 작업량 | 핵심 800~1,100시간의 산술 일정 | 백그라운드 포함 1,000~1,500시간 |
|---|---:|---:|---:|
| 2명 × 주 40시간 | 56시간/주 | 약 15~20주 | 약 18~27주 |
| 1명 × 주 40시간 | 28시간/주 | 약 29~40주 | 약 36~54주 |
| 2명 × 주 20시간 | 28시간/주 | 약 29~40주 | 약 36~54주 |
| 1명 × 주 20시간 | 14시간/주 | 약 58~79주 | 약 72~108주 |

범위의 상·하한은 각각 올림한 값이다. 이 표는 운영이 계획 여유 안에 들어간다는 조건의 산술 일정이며 인허가·검수자 확보·테스트 모집·심사 대기를 포함한 출시 약속이 아니다. 외부 대기 중 독립 작업은 진행할 수 있으므로 모든 대기 기간을 일괄 더하는 것도 피한다. 착수 2주 후 실제 처리 시간을 반영하여 다시 계산한다.

예를 들어 주 20시간의 1인 팀은 데이터·지원 20% 상한이 주 4시간이다. 데이터 문서의 주 5.5시간 운영 예시는 이 상한을 넘으므로 같은 카탈로그 규모를 그대로 유지하며 위 일정을 적용할 수 없다. 자료 수를 줄이거나 안정적인 제휴 자료로 좁히거나 별도 운영 협력을 확보한 뒤 다시 산정한다.

1인·파트타임·숙련도 차이를 같은 일정으로 처리하지 않는다. 공개 날짜는 실제 작업률과 데이터·기기·법률·스토어 의존조건을 확인한 뒤 정한다. 양 OS의 백그라운드 알림을 고정 날짜에 반드시 공개한다고 약속하지 않는다.

## 4 역할과 부재 대응

| 업무 | 2인일 때 | 1인일 때 |
|---|---|---|
| 모바일·기기·위치 | A 주도, B 과업·권한·회귀 확인 | 핵심 UI부터. Android 실기기·외부 시험 협력 확보 |
| BE·AWS·릴리스 | B 주도, A 복구 절차 확인 | 정적형 또는 단일 BE 선택. 인프라를 추가하지 않음 |
| 원문과 규칙 | 한 명 작성, 다른 명 실제 원문 검수 | 외부 실제 검수자 확보. 없으면 고위험 사전 탑재 계산 보류 |
| AI | 필요할 때 기존 담당자가 사용 | 수동 작성이 더 빠르면 AI 도입 보류 |
| 법률·권리·스토어 | 실제 계약·신고 주체가 책임, 외부 자문 | 이름뿐인 전담 법무·SRE·AI 역할을 가정하지 않음 |
| 비상 차단 | 주담당과 대리 접근·절차 확보 | 부재 전 자동 알림·위험 데이터 중지 계획 |

독립 검수는 이 프로젝트의 품질 정책이다. 외부 법률자문이 금액 산식 검수까지 했다고 표시하지 않는다. 서로의 비밀번호를 공유하는 대신 대리 역할과 MFA 복구를 준비한다.

## 5 첫 2주에 할 일

아래의 주차는 착수 후 초반 순서다. 파트타임이라면 같은 작업이 2주를 넘을 수 있다.

1. 실제 가용시간·기술 경험·예산·계약 주체와 보유 Mac·iPhone 모델·OS를 기록한다. Android 실기기 대여 또는 구입 시점과 테스트 모집 경로를 정한다.
2. 한 React Native 프로젝트에서 두 OS를 빌드하고 iPhone에 서명한 개발 앱을 올린다. Docker BE에 기기에서 연결하고 운영용 HTTPS와 구분한다.
3. 생활권 한 곳과 2~3개 브랜드를 골라 공식 자료 10건을 조사한다. 계산 가능성·권리·원문 변경률·실제 검수 시간을 기록한다. 허가되지 않은 자료를 연구에서 운영 카탈로그로 옮기지 않는다.
4. 최근 결제 사례를 가진 사용자 10~15명에게 지원 목록·조건 확인·입력형 과업을 확인한다. 개인정보를 수집하는 현장 연구의 동의와 보존도 준비한다.
5. 위치·알림·단말 배포 데이터 흐름을 가지고 기관·외부 자문에 확인할 질문을 준비한다. 공용 서비스의 위치 기능을 켜기 전에 필요한 절차를 해결한다.
6. iPhone에서 실제 매장·보행·횡단보도·정류장·잠금·종료·권한 거절을 관측한다. 2분 후 실행 기회가 없으면 그 사실을 기록한다. 공개 파일럿 전에 법률·동의·데이터 조건을 통과한다.
7. 원문 자료 작성과 검수에 걸린 시간으로 범위를 조정한다. 백그라운드 가능성 시험을 2~4주 이내 우선 완료하고 결과에 따라 제품 약속을 확정한다.

이 단계에서 데이터 공급 또는 전경 제품의 가치가 막히면 AWS 서비스·AI 자동화·복잡한 쿠폰 조합을 먼저 늘리지 않는다.

## 6 AWS 비용 가정

2026년 9월 30일 확인한 AWS 공식 단가를 사용한다. **서울, 월 730시간, USD, On-Demand, Linux ARM64, Free Tier·크레딧·할인·세금·환율 제외**다. CloudFront는 한국을 포함하는 Asia Pacific edge 단가다. 사용량은 비교용 가정이며 고객 수 예측이나 확정 견적이 아니다.

ALB LCU는 요청 수뿐 아니라 연결·전송량·규칙 평가에 따라 변한다. IPv4 주소도 규모에 따라 늘 수 있다. API 1M와 카탈로그 CF 1M는 서로 다른 요청량 가정이다. 같은 Fargate 크기의 x86_64는 CPU 0.04656·RAM 0.00511 단가로 월 24.46, 같은 전체 가정은 약 106.44다.

초기 서버 관리예산은 **월 120~200 USD와 아래 별도 항목**을 제안한다. AWS 생성 전에 실제 Calculator와 계정 조건을 대조하고 최초 청구 후 수정한다. 인프라 예산을 초과하면 원인을 먼저 확인하고 기능·로그·환경을 줄인다. DB·API를 무인증 공개하는 방식으로 비용을 줄이지 않는다.

### 비용에 포함되지 않은 항목

- DB 백업 포함량 초과·별도 snapshot·복구용 임시 DB·저장 확장·CPU credit·Extended Support·초과 IOPS.
- NAT·interface endpoint·AZ 간 전송·추가 IP·배포 중 추가 task·높은 LCU·로그 증가.
- custom metric·alarm·Insights·전량 WAF 로그·KMS 사용자 관리 key·premium WAF 규칙·Support plan.
- 관리자 인증의 유료 기능·오류 SDK·macOS CI·EAS·LLM·OCR·지도·데이터 사용료.
- 도메인 등록·스토어 회비·Android 기기·외부 검수·법률자문·개발자 시간·세금·환율.

개발은 로컬 Docker를 기본으로 하고 AWS 개발 환경은 필요할 때 켠다. 서비스 task를 내리는 것만으로 ALB·RDS·IP의 요금이 모두 없어지지는 않는다. 폐기할 환경은 저장해야 할 데이터와 백업을 확인한 뒤 리소스별 정리한다.

### 비용과 책임이 다른 대안

## 7 개발 외 현금 예산

Apple Developer Program은 통상 99 USD/년, Google Play 등록은 25 USD 일회 요금이며 지역별 결제 금액·세금·계정 조건을 확인한다. 원화 환율을 임의 고정하지 않는다. [Apple 등록](https://developer.apple.com/programs/enroll/), [Google Play 등록](https://support.google.com/googleplay/android-developer/answer/6112435?hl=en)

| 예산 항목 | 계산 방식 |
|---|---|
| 인프라 | 실제 운영 월수 × 월 계획예산. 예: 3개월이면 360~600 USD와 별도 항목 |
| 스토어 | 첫해 기준 위 99 + 25 USD를 출발점으로 실제 지역 청구 확인 |
| 기기와 개발 Mac | 기존 기기 적합성 확인 후 부족한 것만 구입·대여 견적 |
| 데이터와 검수 | 허가 협의·사용료·외부 검수 건수에 따른 실제 견적 |
| 법률과 개인정보 | 서비스 흐름·사업자 자격·국외 처리·동의 문구 검토 견적 |
| 사용자 시험 | 실제 모집·참여 보상·이동 시간과 개인정보 운영 비용 |
| 인력 기회비용 | 실제 개발·검수·시험·운영 시간 × 합의한 시간당 가치 |

개발자 시간의 가치는 실제 합의한 시간당 기준으로 계산하고 외부 업무는 견적으로 산정한다. 개발자 시간을 무료로 계산하면 현금 부담은 줄어도 유지 가능성 판단에서 시간 비용은 남는다.

## 8 스토어와 기기 조건

| 항목 | 2026년 9월 30일 확인한 조건과 적용 |
|---|---|
| Apple 업로드 | 2026-04-28부터 Xcode 26 이상과 iOS 26 SDK 이상 요구. 2026-09-09부터 제출 앱의 deployment target은 iOS·iPadOS 13 이상. RN·라이브러리가 더 높은 최소 OS를 요구할 수 있음 |
| Android 제출 | 신규·업데이트 앱의 일반 target SDK는 2026-08-31부터 Android 16 API 36 이상. 최소 실행 OS와 target SDK는 다른 값 |
| Play 신규 개인 계정 | 2023-11-13 이후 생성 개인 계정은 12명 이상이 14일 연속 opt-in한 closed test 등 적용 조건을 확인. 이후 production access 신청이며 자동 승인 아님 |
| Play 기기 확인 | 해당 신규 개인 계정의 기기 확인에는 비루팅 Android 10 이상 실제 기기가 필요. iPhone·에뮬레이터로 대체하지 않음 |
| Android 네이티브 호환 | RN·Hermes·네이티브 SDK와 최종 AAB에서 생성한 APK의 16 KB page size 호환·정렬·실행을 확인. 당시 공식 문서의 제출·업데이트 제한 일정도 확인 |
| 배경 위치 | 핵심 가치·설명·최소 권한·영상·신고 등 플랫폼 요구를 실제 구성에 맞게 준비. 할인 안내만으로 승인 보장 없음 |
| 개인정보 | 실제 SDK·packet·로그·권한을 App Privacy·Data safety·정책과 대조. 로컬 지갑이라는 이유로 모든 수집 없음 표시 금지 |

공식 근거는 [Apple 제출 요구](https://developer.apple.com/news/upcoming-requirements/), [Android target API](https://developer.android.com/google/play/requirements/target-sdk), [Play 개인 계정 테스트](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en), [Play 기기 확인](https://support.google.com/googleplay/android-developer/answer/14316361?hl=en), [Play 배경 위치 정책](https://support.google.com/googleplay/android-developer/answer/9799150?hl=en), [Apple Review](https://developer.apple.com/app-store/review/guidelines/)이다. 제출 시점에 다시 확인한다.

16 KB 조건은 [Android 공식 page size 문서](https://developer.android.com/guide/practices/page-sizes)를 따른다. 문서 조사 시 target API 35 이상 앱의 64bit 호환과 2027-02-01 업데이트 제한 안내를 확인했다. 에뮬레이터의 일반 실행만으로 모든 네이티브 바이너리가 이 조건을 만족한다고 판단하지 않는다.

iOS 26 SDK로 빌드한다는 것은 모든 사용자 기기가 iOS 26이어야 한다는 뜻이 아니다. 실제 지원 최소 OS는 선택한 RN·네이티브 모듈·보유 테스트 기기·지원 예산을 확인하여 결정한다. Android도 API 36 target과 실제 최소 OS를 나눈다.

TestFlight와 Play testing track의 release 모드에서 운영과 구분된 환경을 사용한다. 스토어 계정·서명·버전·지역·검수 메모·기능 설명·지원 연락처·정책 URL을 준비한다. 두 스토어는 각자 승인되므로 동시 날짜를 고정하지 않는다. iPhone으로 먼저 검증하되 Android의 기본 빌드는 처음부터 유지한다.

## 10 운영 가능한 약속

일반 제보는 초기 제안으로 평일 하루 한 번 확인하고 2영업일 안에 분류한다. 데이터 변경은 약속한 확인 주기에 처리한다. 실제 담당자가 결정하기 전 지원 시간이나 응답 보장을 사용자에게 게시하지 않는다. 1~2인 팀에 맞는 지원창과 대리·부재 대응을 준비한다.

금액 오류·권리 철회·보안 사건은 일반 inbox와 구별한다. 인지한 위험 규칙을 즉시 운영 차단하는 목표를 두고, 온라인 앱의 다음 동기화와 최대 24시간 안전 확인 기한을 분리한다. 모든 오프라인 기기에서 15분 내 사라진다고 약속하지 않는다. 운영창은 법정 사고 통지·신고 시간을 멈추지 않는다.

주간에는 자료 변경·계산 회귀·제보·비용·실패 장소를 확인한다. 데이터와 지원이 팀 가용시간의 20%를 2주 연속 넘으면 신규 커버리지 추가를 동결한다. 부재 때는 위험한 규칙과 자동 기능을 먼저 중지하며, 검수자가 없는데 확인일만 갱신하지 않는다.

초기 KPI는 과업 성공, 지원 수단·점포 커버리지, 미확인 비율, 제보 재발, 실제 운영시간, 알림 적절성·차단으로 둔다. 청구내역을 받지 않으므로 실제 절감액을 정밀 증명했다고 주장하지 않는다. 계정·안정적 식별자 없이 전체 사용자 유지율을 정확히 계산한다고 약속하지 않고 동의받은 파일럿 관찰과 선택적 집계부터 검토한다.

초기 서비스는 무료 검증판으로 두며 광고·카드 발급 중개·제휴 수익·유료 지갑·B2B는 실제 공급·신뢰·결제·플랫폼 정책 검토 후 별도 결정한다. 후원 상품을 예상 할인 순위에 섞지 않는다.
